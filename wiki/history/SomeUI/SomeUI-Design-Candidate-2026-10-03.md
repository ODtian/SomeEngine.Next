## 1. 三者的含义保持一致

| 内容 | 含义与存储职责 |
|---|---|
| 控件 struct | 普通 C# 参数值，以及处理这些参数的构建方法。接受后的参数保存在对应实体的同类型 ECS 组件中。复制与字段赋值遵循 C# 值语义。 |
| 控件实例 | Game world 中持久的 ECS 实体，保存控件参数、层级关系、交互状态和生成的界面数据。 |
| 计算记录 | 保存实体、执行入口或闭包、读取依赖与版本、输出标识；服务于重算、复用和生命周期。 |

应用音量的主值位于应用 ECS 组件。滑杆、旋钮、文字的参数属于界面投影，接受后直接成为控件实体的组件。参数比较读取现有 ECS 值，新声明属于本轮临时数据。交互状态表达指针、拖动等持续过程，持续保存在对应实体或行为的状态组件中。

```csharp
var first = new Slider { Value = 0.3f };
var second = first;
second.Value = 0.8f;
```

这里形成两个普通局部值。实例在声明被执行器接受时建立，后续声明通过实例身份更新它。

## 2. 一个构建接口，三个构建动作

```csharp
public interface IView : IComponent
{
    void Build(ViewTree tree);
}

public delegate void Rebuild(ViewTree tree);
```

`ViewTree` 是本次求值使用的短期上下文，可以采用 `readonly ref struct`。其三个构建动作是：

- `Add(in value)`：声明一个结构体子控件；匹配已有实例，或建立新实例。
- `Compute(callback)`：声明一个具有独立依赖和输出范围的计算区域。
- `Set(in component)`：声明当前实例的 ECS 组件结果，比较后提交。

读取数据、取得实例状态和读取主题属于这些计算的数据访问能力。`Compute` 每次调用保存的闭包时传入本次的 `ViewTree`，让短期上下文跟随当前求值。

这个上下文只持有 World、当前实体、当前计算标识和本轮共享输出缓冲的访问。控件包含关系存储在 Game world 的层级数据中。每个计算产生哪些实体、组件和资源的归属记录持续保留，用于下一轮匹配与释放；这些是调度元数据。

调用某个控件的 Build 时，从其 ECS 组件读取参数，形成临时执行副本，通过具体泛型类型调用构建方法。持续状态的更新走 ECS 写入入口。相关 ECS 借用结束后批量提交结构变化和组件结果。

默认按所属计算中的声明位置匹配。动态列表使用业务实体或整数键；有独立状态含义的条件分支使用明确的分支键。常驻节点在计算记录中保存实体句柄。

`Compute` 保存独立的计算和输出范围，沿用所在控件实例。每个 `(实体, 组件类型)` 的声明结果由一个存活的计算负责，其他计算通过读取该结果或声明自己的子控件组合它。区域重建时先确定输出范围的保留、移交和退出，再提交对应组件；释放区域时据此释放它负责的输出。

`Add` 收集子声明。当前构建成功结束后，先比较并应用该构建的 `Set` 结果、登记本轮子声明转换，再执行参数投影和子构建。因此，同一父构建登记的主题与子声明转换对其本轮子构建生效。构建中的 ECS 读取返回已提交的数据；本轮正在组装的数据通过普通局部变量继续计算。依赖求值阶段结束后，再进入布局和绘制处理。

## 3. 内置与用户控件共用构建入口

以下代码用于表达组织关系；`NumberInput`、几何原语等属于后续需要定义的公共类型。

```csharp
public struct Slider : IView
{
    public float Value;
    public float Minimum;
    public float Maximum;
    public float Step;

    public readonly void Build(ViewTree tree)
    {
        tree.Set(new NumberInput<HorizontalDrag>
        {
            Value = Value,
            Minimum = Minimum,
            Maximum = Maximum,
            Step = Step
        });

        var style = tree.Theme<SliderStyle>();
        tree.Add(new SliderTrack
        {
            Value = Value,
            Minimum = Minimum,
            Maximum = Maximum,
            Style = style
        });
    }
}
```

行为以具体的 ECS 数据及类型化处理实现。`Set` 更新行为所读取的配置；组件首次出现、数据变化和组件移除分别触发生命周期处理。拖动状态独立保存在实例的 ECS 组件中。

声明结果随其输出范围存在，持久交互状态随对应实例或行为存在。状态取得在首次使用时初始化。替换拖动解释类型时结束旧行为的捕获和拖动过程，外围实例自身的焦点等状态按实例身份继续保留。

用户的 `Knob` 同样实现 `IView`，使用相同的数值行为，选择适合旋钮的拖动解释，再声明自己的圆弧、刻度和文字。每个控件的构建代码写一份。

内置构建方法通过泛型约束调用，控件参数按具体类型保存。响应式闭包与委托属于计算记录，ECS 界面组件保存具体数据。

## 4. 两种求值粒度来自读取位置

整段声明求值：

```csharp
public void Build(ViewTree tree)
{
    var audio = tree.Read<AudioSettings>(Mixer);
    tree.Set(new SetVolume { Mixer = Mixer });
    tree.Add(new Slider { Value = audio.Volume, Maximum = 1 });
    tree.Add(new Knob { Value = audio.Volume, Maximum = 1 });
}
```

局部求值：

```csharp
public void Build(ViewTree tree)
{
    var mixer = Mixer;
    tree.Set(new SetVolume { Mixer = mixer });

    tree.Compute(current =>
    {
        var audio = current.Read<AudioSettings>(mixer);
        current.Add(new Slider { Value = audio.Volume, Maximum = 1 });
    });

    tree.Compute(current =>
    {
        var audio = current.Read<AudioSettings>(mixer);
        current.Add(new Knob { Value = audio.Volume, Maximum = 1 });
    });
}
```

两段代码使用同一份 Slider 与 Knob。第一次写法把音量依赖登记在父构建；第二次写法把依赖登记在各计算区域。区域内部使用普通 C# 条件和循环生成声明。

结构体成员先复制为局部值再供闭包捕获。ECS 组件引用在闭包实际执行时取得，引用的使用范围跟随当前数据访问。

## 5. 控件对等与子声明转换

内置控件和用户控件统一实现 `IView`，具有相同的独立使用、参数更新、组合与生命周期能力。例如用户的圆形滑块本身就是普通控件：

```csharp
public struct RoundThumb : IView
{
    public Vector2 Position;
    public float Radius;
    public Color Color;

    public readonly void Build(ViewTree tree)
    {
        tree.Set(new CircleData
        {
            Position = Position,
            Radius = Radius,
            Color = Color
        });
    }
}
```

它可以直接通过 `Add(new RoundThumb { ... })` 使用。内部定制需要的额外能力位于子声明数据上：作用范围内的控件参数先经过普通 C# 转换，转换结果仍然通过共同的 `Add` 执行。

```csharp
tree.Map((SliderThumb thumb) => new RoundThumb
{
    Position = thumb.Position,
    Radius = thumb.Size * 0.5f,
    Color = thumb.Color
});

tree.Add(new Slider { Value = 0.4f, Maximum = 1 });
```

`Map<TFrom, TTo>(Func<TFrom, TTo>)` 的两个类型均为实现 `IView` 的 struct。C# 可以从显式 lambda 参数和返回值推导类型。控件实现始终通过类型接口提供，闭包表达普通参数投影。内置到用户、用户到内置、用户到用户的转换采用同样的路径。

转换按类型和树中作用范围匹配，同型声明可以进一步按既有值类型键区分。一次声明接受参数转换后，以最终的控件类型和键匹配实例；目标类型改变时建立相应的新实例。目标构建产生的后代作为各自独立的声明处理。直接复用原构建方法时使用普通 C# 方法调用。

父计算重新登记普通转换闭包时，更新其捕获，并使作用范围内相关子声明的生成计算重新求值。生成者从自己的当前 ECS 参数重新产生源控件值，再计算最终控件值并与 ECS 中接受的参数比较。输出记录保留源类型、键与生成计算的关联。转换变化产生的构建成本计入该范围的实际更新工作。目标控件在自己的构建中读取所需主题和状态；转换本身用于表达输入值之间的关系。

转换 SliderThumb 时，外围 Slider 的行为声明和状态继续保留。转换整个 Slider 时，目标控件通过共同的行为组件选择数值能力。内置与用户控件的身份都由最终声明决定。

## 6. 主题来源

主题是应用或祖先范围提供的类型化数据。内置提供 SliderStyle 的默认值，用户可以定义 KnobStyle；构建方法通过 `Theme<T>` 读取所处环境中对应的数据。

主题解析维护一个明确的层级：完整默认值、主题覆盖、状态覆盖、实例覆盖。覆盖采用类型化字段选择，保留显式零值与省略字段的区别。

主题读取登记在实际执行读取的计算中。计算将主题结果与控件值组合，产生布局或绘制组件。颜色、尺寸、主题范围及相关交互状态的变化分别影响相应依赖。子声明转换与主题数据分别表达结构定制和数值定制。

## 7. 更新与跳过的具体规则

| 条件 | 执行与复用 |
|---|---|
| 首次声明 | 创建实例及计算记录，执行 Build，登记读取，提交组件并建立子项。 |
| 计算输入和自身依赖继续有效 | 复用已有输出。 |
| 父提交新的子控件值 | 更新参数；能够证明参数等价且自身依赖有效时复用，否则执行子 Build。 |
| 子控件自身观察来源变化 | 子计算独立进入调度，父计算按其自己的依赖决定执行。 |
| 父重新声明已有 Compute | 替换闭包并执行一次，使用新的捕获和读取集合。 |
| 子节点的源参数相等，但主题或子声明转换变化 | 对应主题依赖或参数投影重新求值，随后按普通结果比较决定后续工作。 |
| 某个可观察结果经比较相等 | 复用依赖该结果的下游计算；当前计算的依赖登记与输出范围匹配仍然完成。 |
| 最终组件结果相等 | 复用该组件驱动的后续数据。 |
| 列表键和类型保持、顺序改变 | 保留实例和交互状态，更新顺序及受影响的布局与绘制。 |
| 子项退出 | 释放对应实例、依赖、闭包引用和实例资源。 |

参数等价需要类型提供可靠的比较语义，影响结果的可变数据通过观察读取表达。普通 struct 身份、委托身份与计算结果等价分别处理。内置的纯值参数可以提供字段比较；其余输入送达时执行构建。

当前 `Compute(Rebuild)` 通过声明子控件和组件产生结果，跳过判断落实到这些具体结果。计算执行结束的事实本身与其各项结果分别记录。

首次登记后，计算记录保存闭包。父构建重新执行到捕获 lambda 时，C# 会再次对该 lambda 求值，其分配取决于生成代码。新闭包替换旧闭包，更新后的捕获至少参与一次求值。较少重跑的外层区域能够长期保留细粒度闭包；实际发生的构建求值保留普通 C# 执行语义。

## 8. ECS 双向流程与实例状态

源数据保留真实字段与原生写引用，例如 Job 的 `Execute(ref AudioSettings audio)` 修改 `audio.Volume`。可写访问与写入完成边界提供组件或块的变化信息，观察计算在相关写入可见后读取当前值。

界面计算通过 `Set` 声明组件结果，提交阶段比较旧值并写入实际变化。计算缓存用于比较，ECS 组件是后续系统消费的界面数据。

接受后的控件参数同样使用 ECS 的变化版本。直接通过写入入口修改某个 Slider 组件，可以调度该实例的 Build；父计算再次提交该控件时，最新声明成为该组件的参数。常规业务绑定由 AudioSettings 等业务组件保存持续主值，控件参数保存其界面投影，使这两类写入的职责明确。

输入事件由结构体处理器消费。连续步进表达为有序增量，在业务源的当前值上应用；拖动表达为基于拖动过程计算的目标值。源写入结束后推动界面计算，交互状态仅保存拖动与焦点等过程需要的数据。

两种声明方式使用同一个业务写回处理器：

```csharp
public struct SetVolume : IOn<NumberEdit>
{
    public Entity Mixer;

    public readonly void Handle(Input input, in NumberEdit change)
    {
        ref var audio = ref input.Edit<AudioSettings>(Mixer);
        audio.Volume = change.Apply(audio.Volume);
    }
}
```

`IOn<T>` 是结构体事件处理接口。`NumberInput` 在源控件产生 `NumberEdit`，事件沿实例父子关系送到最近的对应处理器。上面的两种页面写法都在公共父范围用 `Set` 登记 `SetVolume`，因此滑杆与旋钮共同更新 Mixer 实体上的同一份音量。处理器字段变化更新已有登记，组件退出时释放对应登记。

正常更新顺序是输入或 Job 写入完成、收集变化、计算求值并提交该计算的结果、执行受影响的后续计算、相应行为与外观处理、布局与绘制数据更新。同一轮依赖按有向无环关系求值；布局和绘制开始前，当前有效的界面更新队列完成处理。父构建的输出和本轮子声明转换先确定，子构建随后匹配并执行。业务事件在指定的输入写入阶段处理；后续输入响应可以启动后续更新轮次。最终绘制数据沿 Game world 到 Rendering world 的既有路径传递。

## 9. 存储与性能成本

| 长期数据 | 存储位置 |
|---|---|
| 应用音量 | 应用实体的 AudioSettings 组件 |
| 接受后的 Slider、Knob 等参数 | 控件实体的同类型 ECS 组件 |
| 父子关系、顺序、实例键 | Game world 的层级数据 |
| 拖动、焦点等状态 | 对应实体或行为的状态组件 |
| 布局与绘制数据 | Game world 的界面输出组件；随后按引擎路径提取到 Rendering world |
| 调度与输出归属 | 按类型或紧凑记录组织的实体标识、版本、依赖、执行入口和输出标识 |

构建上下文是短期值。提交缓冲按实际输出使用并复用存储。常驻控件的参数比较读取 ECS 当前值；基本几何能够直接供系统消费的数据优先使用现有组件。

一次更新的成本按以下部分分别核算：

```text
变化收集
+ 依赖调度
+ 实际执行的 Build / 闭包
+ 发出的子声明及身份匹配
+ 参数和结果比较
+ ECS 数据提交与结构变化
+ 分配与回收
```

- 变化收集取决于 ECS 记录的粒度。块版本方案包括受观察块的检查和保守唤醒；实体组件级记录可以直接定位相应观察者。
- 参数相等节省对应子构建。已经执行的父构建、临时值构造和子声明匹配仍计入本轮成本。
- 组件结果相等节省对应后续系统、布局与绘制工作，之前的求值与比较成本照常计入。
- 泛型约束调用与类型化列存储保留具体结构体类型；实例和参数通过具体类型存储，调度入口按类型共享。
- 每次构建读取参数形成临时副本，成本与参数大小有关。大参数、可变引用和比较函数分别测量。
- 已登记的闭包可反复调用。父构建再次经过捕获 lambda 时，委托及捕获环境按 C# 生成代码计算分配成本。字符串格式化等用户代码也计入实际分配。
- 子声明转换在实际声明求值期间执行。转换关系变化会重新执行相应生成计算；普通样式值变化优先沿主题数据依赖传播。
- 悬停、按下、焦点和拖动进度优先使用已有状态组件的字段。创建、移除、控件类型变化和实际能力变化承担 ECS 结构修改成本；这类修改集中提交。

性能验证分别记录变化扫描量、构建与闭包执行次数、参数比较量、组件写入量、结构修改量和托管分配，并与布局、绘制时间共同分析。渲染优化的最终验证沿用项目规定的统一场景和采样方式。
