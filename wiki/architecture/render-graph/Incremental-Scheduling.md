# Incremental Scheduling

## Definition
排序关系变化后只修复受影响的 DAG 区域。

## Invariants
- 从 predecessor/successor 发生变化的 pass 开始。
- 沿真正受影响的相邻节点传播。
- 已缓存结果与新结果一致时停止传播。
- 不因为一个局部 edge 变化重新排序整个 graph。

## Current design
具体动态拓扑算法可替换；本页只固定局部更新语义。

资源的版本顺序分析共用当前显式依赖的祖先搜索结果。每轮依赖分析按实际查询的
pass 计算祖先位集，资源通过与自身使用者相交获得排序约束，随后按声明顺序处理
同时就绪的使用者。搜索工作区随下一轮分析刷新，显式依赖仍由原图数据持有。
包含循环的关系沿原资源投影处理，资源版本及有效 pass 的循环检验保持原行为。

`AnyCompatible` 在命令类型支持的队列中选择最早可开始执行的队列。生产者与
消费者的跨队列次数用于开始时间相同的选择。编辑影响的 pass 沿用当前拓扑顺序
重新选择队列，队列可用时间包含前序工作及资源依赖的完成时间。

提交批次在跨队列消费者需要的生产者之后结束，并在引入新的跨队列等待之前开始。
相邻批次合并时同时保持已有等待和消费者的释放时机。一个提交中的多份命令列表
一起交给后端，供 GPU 重叠执行相互独立的工作。

应用在普通颜色目标上完成 tone map、界面合成与读回，再由最终 copy pass 写入交换链
图像并返回 `Present/NoAccess`。各合成步骤沿自身资源依赖调度，图像获取由最终提交持有。
