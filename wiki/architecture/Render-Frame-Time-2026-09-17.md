# 2026-09-17 render 工作树优化与验收

## 目标与基线

目标是完整单帧低于 1 ms，而不是 CPU 某个阶段低于 1 ms，也不是多帧流水的平均提交间隔。本轮没有达到这个目标。

工作树为 `F:\SomeEngine.Next-render-enhancement`，分支 `codex/render-enhancement`，起点 HEAD 为 `4b87345c`。开始工作时已有大量未提交改动；对照基线是这些改动的构建结果，不是干净 HEAD。没有回退既有修改，也没有创建提交。

本机为 Xeon E5-2698B v3、RTX 3080，Windows 显卡驱动版本为 32.0.16.1074。完整帧测试使用 Release、D3D12、1280×720。分辨率、场景数量、细分限制、材质解释、阴影及 TAA 均未为计时降低或关闭。生成场景只用于验证，并没有进入引擎分支条件。

## 保留的修改及局部性依据

### 持久表沿路径复制

`GraphTable.cs` 原先在第一次修改共享数据页时复制整份页目录。每页 64 行虽然限制了数据页复制量，却没有限制目录复制量；修改一行仍可能复制与全表容量成正比的目录。

现在使用每层 32 个子节点、每页 64 行的持久基数树。创建编辑分支只共享根并更换写入标记，不遍历行或目录。第一次写某页只复制根到该页的目录路径以及该数据页；同次编辑重复写同一路径时复用已复制节点。分支之后，两边均不能直接写共享节点。增加树高时只增加一个根，不移动已有子树。

设已分配的目录容量对应的数据页数为 P（删行不会缩根），目录高度为 h，单行修改最多复制 h 个 32 项目录和一个 64 行数据页，额外复制量为 O(32h+64)，h=O(log32(P))。创建分支为 O(1)。读取由旧目录的直接索引改为 O(h) 路径读取，不能只报告写入收益而忽略这一取舍。删除尾行会清空其引用，不复制其余页；上层交换删除至多修改被交换的几行路径。空根为共享只读节点，首次写入才分配。

`GraphStorage.cs` 的行集合分支构造也不再先创建三份空表、随后立即覆盖它们。行内容的按需复制、旧帧可见数据以及废弃编辑中已发放标识的失效规则保持不变。

这里证明的是表分支及行修改，不是整个渲染图的一切修改都具有常数复杂度。资源范围或依赖改变仍需处理受影响资源访问、依赖闭包及队列边界；影响扩展至全图时不能宣称只处理一个节点。既有的临时上传声明和按帧输入更新没有在本轮全部重写。

### 提前录制，按依赖提交

增加 `FrameSubmissionMode.RecordAhead` 和 `FrameRecordingAhead.cs`。依赖、屏障、资源和参数连接确定后，提前启动允许工作线程执行的录制批次。调用线程专属回调仍由调用线程执行；提交一个波次之前等待该波次所需录制完成，并继续使用原来的队列依赖和 GPU 完成条件。

可并行的依据是：每个批次使用独立录制上下文和结果位置；录制读取已确定的图数据；提交仅更新完成信息和资源边界结果，不改这些任务正在读取的命令声明。执行图结构仍通过显式编辑接口修改，本路径没有创建一份每帧重新生成的图。

新模式明确允许前面的提交在后面的录制失败前成功。发生异常时仍等待所有已启动录制任务，包括后续波次，然后才由外层清理未提交命令或归还帧内存。原有两种模式及其异常语义不变。入口选择新模式；移除了旧的第 100 次录制诊断输出。

### VRB、软件光栅与用户定义顶点

直接核对 EpicGames/UnrealEngine 5.8.2 的 `NaniteEncodeVertReuseBatch.cpp`、`NaniteRasterBinning.usf` 和 `NaniteRasterizer.usf` 后，删除了此前 5 批次上限、剩余三角形强制改走硬件以及 64 项组共享顶点缓存。离线构建现在按材质范围生成完整顶点复用批次，每批最多 32 个唯一顶点和 32 个三角形；前三个材质范围使用与 UE 快路径相同的 4-bit 批次数表和连续 5-bit 三角形数编码，四个 32-bit 字完整保留全部批次。

随后顶点模型进一步收敛为用户定义类型。Cluster 只保存 opaque vertex blob 和 `VertexEncoding` 兼容标识；`IVertexEvaluate.Vertex`、visibility varying、domain triangle、domain surface 都是编译期用户类型。核心管线不再枚举 Normal、Tangent、UV 或其他固定顶点字段。标准材质仍可定义这些字段，但只属于标准材质库。

普通软件光栅现在也以完整 VRB 为 wave 工作粒度。一个 32-thread wave 最多接收 32 个三角形和 32 个唯一顶点；每个唯一用户顶点只由一个 producer lane 求值，并由用户实现的 `readLane()` 搬运完整 opaque vertex / visibility varying。这样不需要 UE 固定 `FCachedVertex` schema，也不需要引擎猜测用户顶点布局。需要细分的路径继续使用同一 VRB 不变量。

visibility raster 也改为用户闭环：用户定义 `Varying`、vertex→varying、跨 lane 搬运、细分顶点 varying 生成、SW 像素插值以及最终 Visible/Depth 判定。HW VS/MS→PS 使用用户 varying 的原生 shader stage interpolation；SW 提供原始三角形的 perspective/linear barycentric 及其 x/y 导数给用户插值函数。VisBuffer 格式没有扩展，仍只持久化可见 cluster/triangle 身份与深度胜者。

现在不存在“编码空间不够就产生剩余批次”的语义；元数据容量不再参与软/硬光栅选择。相关 DXIL/SPIR-V 与默认网格资源均已重新生成。

注意：本报告后面的完整帧性能表是在上述 opaque vertex / visibility varying 重构之前采集的历史测量，不能作为当前全 VRB SW 路径的性能结论。当前结构已经重新做功能、编译和 GPU 校验，但尚未按同一 ABBA 口径重新测完整帧性能。

### 实际场景读回

新旧版本分别运行 120 帧，固定步长、逐帧 GPU 完成等待，启用 GPU 校验及最终呈现像素读回。覆盖默认静态、默认运动、稀疏运动、光照运动、材质变化、动态遮挡、纹理位移、顶点变形与透明裁剪，以及后两者的无网格着色器硬件回退，共 10 组前后对照。

其中 8 组最终呈现像素逐字节一致：稀疏运动、两组光照/材质、遮挡、两组位移、两组顶点变形/透明裁剪。动态遮挡报告二阶段最多恢复 48 个簇。位移的混合及硬件回退路径均未报告细分容量丢弃，但仍报告触及原有细分质量限制，本轮没有提高该限制，也不能把它当作没有质量边界。

默认大场景的阴影开启结果不是逐像素重复的：旧版本自身重复运行、新版本自身重复运行均出现不同像素。单独关闭阴影、保留 TAA 的诊断对照中，静态和动态的新旧输出分别一致。该诊断将差异定位到阴影相关路径，但不构成对阴影开启时严格逐像素等价的证明。正式性能结果始终开启正常阴影和 TAA；关闭阴影的数据没有混入性能表。

## 计时口径

每次运行 2,000 帧，预热剔除最初 500 帧，统计后续 1,500 个完整帧。固定步长为 0.016666667，使用 `--synchronous-frames --hidden-window --no-vsync --no-debug-ui --trace-frames-only`。正式计时关闭 GPU 校验和像素读回，避免把校验开销计入；没有关闭实际渲染功能。完成等待仍在计时范围内。

同一场景目录中交换代码和对应编译资源，不重新生成几何或随机标识。首先按旧、新顺序比较全部场景，再对默认静态、默认运动、位移和顶点变形/透明裁剪按新、旧顺序复测。另以相同的新代码分别使用旧、新着色器作消融对照。测试、编译和其他渲染进程均在正式计时前结束。

完整帧追踪与带详细范围、分配量的瓶颈追踪分开。详细静态追踪中的图依赖分析约 0.010 ms，而 GPU 完成等待、原生提交、呈现明显更大。这个剖析只用来找瓶颈，不能将其均值与仅帧计时直接相减。

## 局部编辑测量

使用公开接口创建 2,048、65,536、262,144 行的无执行工作图，每次只交替修改最后一个缓冲区的描述并提交。每组先做 64 次预热，再测 512 次编辑，旧、新、新、旧顺序运行。测量当前线程分配量；该试验没有执行 GPU 帧，绝不能当作完整单帧指标。

默认 JIT 设置下，单次编辑分配量分别从约 16,968 / 24,904 / 49,433 字节降至 12,320 / 12,584–12,632 / 12,896 字节。新实现不再随整份页目录增大而线性复制。在合法 int 索引范围内，本表至多经过五层目录；这个上界只约束表的路径复制，不约束其他依赖闭包、垃圾回收或操作系统调度。

另在独立微基准进程中关闭分层 JIT 后复测，正式渲染测试没有使用这一设置。下表保留两次运行的编辑耗时范围，单位为微秒，分配量为字节。

## 交付状态与边界

三个着色器入口已在工作树内重新编译，随后 Release 构建再次通过，Cluster 的 10 项测试再次通过。交付的图程序集与性能测试所用图程序集校验一致。

本轮没有改变场景规模、分辨率、材质解释、阴影或细分预算来获得表中的结果。没有增加第三条场景数据通路，也没有按场景选择图更新或光栅实现。录制提前并不代替结构变更的显式 CRUD，更不代表可以忽略依赖闭包而任意局部更新。

仍未完成的目标是完整单帧低于 1 ms。静态改善有限，位移均值仍超过 12 ms，默认大场景的阴影开启结果也不能宣称跨进程逐像素重复。当前证据不足以承诺所有设备、所有场景均有同样收益，更不能把本轮验收视为对未覆盖功能的全面证明。

报告保留测量口径、结果、复杂度依据与回归边界。临时场景、前后对照构建、追踪、微基准脚本和图像检查文件在结果核对后删除；既有未提交改动保留，不创建提交。
