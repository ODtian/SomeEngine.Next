# RenderGraph 持久结构与渲染热点修复

日期：2026-09-06。实现工作区：`F:/SomeEngine.Next-render-enhancement`。本次落实持久 CRUD、修改驱动的执行数据维护、区间同步、灯光清零与分组建表、临时 heap 排布和提交批次修复。**0.5–1 ms CPU 目标尚未达到**；默认 hybrid/async 场景实测 CPU 帧循环为 12.923 ms，不能把局部分析复用时间当作整个渲染 CPU 成本。

设计说明见 [[Render-Graph]]；问题基线见 [[RenderGraph-Retained-Architecture-Audit-2026-09-05]] 和 [[Render-Enhancement-Performance-Review-2026-09-05]]。本页与 [机器可读结果](RenderGraph-Retained-Delivery-2026-09-06.json)记录本次实现和验证。历史报告保留当时事实，不代表修复后的代码现状。

## 已实现的行为

1. **持久 CRUD。** 存储改为不可变容器共享根与单行写时复制，删除全表复制和外围全图发现变化的路径。显式边、资源访问、视图与绑定关系维护反向索引。标签更新保留依赖结果；相同值 setter 和空提交不会推进结构版本。拓扑逆序边只重排受影响节点，循环拒绝保持事务原子性。
2. **持久属性与执行数据。** Pass 数据、启用状态、pipeline、参数块和可替换的参数绑定流保留到后续执行。各在途帧通过通知更新相关行，资源依赖按来源维护，活跃性、调度、frontier 和生命周期沿实际影响区域传播。移除了按全量输入比较来判断分析是否复用的旧路径。即时上传、readback 和扩展点子图仍可接入。材质修改/重载发出事件，Cluster 无变化路径不再逐个比较全部材质 revision。
3. **区间与同步。** Buffer 使用区间集合，Texture 按 mip/layer/aspect 区域处理；资源变化撤销并重建该资源的同步贡献，随后只重组相关 pass。部分读取保留未读范围的内容，跨队列转移保留不同生产者状态。持久属性更新、外部资源重绑定、内容变化和实际提交后的状态有分别的局部通知。
4. **灯光表。** 删除每帧在 CPU 清空完整灯光 grid/index list 再上传的路径。GPU 清零必要的 grid 计数，消费者只读取有效索引前缀，溢出仍按容量限制。建表由每灯一个线程改为每灯一个 64 线程组，组内协作遍历覆盖 cell；原有投影范围计算保留。通用 D3D12 pattern 填充也改用整字批量写入并处理尾字节。
5. **临时内存。** 删除 128/32 MiB 固定 heap 下限与逐帧排布发现。按实际需求和对齐创建 heap，保留分配、视图和空闲区；合并相邻空闲区，释放全空 heap。生命周期修改后只重新检查冲突区域。修复 GPU 生命周期不重叠但 CPU 同时持有的 upload/readback 错误别名，host-visible 分配不共享地址。
6. **录制与提交。** 多批次路径按队列批量录制，减少逐 pass 作业/上下文开销。前帧迟到释放按来源队列及消费批次合并。修复同队列前驱落到较晚提交批次、后继反而提前提交的问题，并将别名关系加入提交依赖。

资源排布沿用按大小降序、最佳适配的启发式；调度使用受影响连通区域内的优先级选择。它们不保证全局最优。修改确实连接整个图时，传播区域可以覆盖全图；没有声称所有 CRUD 都是常数时间。

## 测量方法

本机为 Xeon E5-2698B v3（16 核/32 线程）和 RTX 3080，D3D12、1280×720、Release/.NET 10，隐藏窗口、关闭 vsync。与历史复核使用同一机器。没有锁定 GPU 时钟。计时程序集来自工作区源码的独立插桩副本，产品源码不带计时探针，最后重新构建普通程序集运行测试。

CPU 矩阵共 8,448 帧，丢弃每轮前半段，保留 4,224 帧。默认静态模式每配置 3 轮×512 帧，交替配置顺序；动态默认、位移和稀疏动态每配置 2 轮×384 帧。表格使用各轮中位数的中位数，P95 给出各轮范围。默认计时关闭诊断和 GPU validation；另有 160 帧诊断轮及四组各 24 帧的 GPU validation/output 验证。

`wallMs` 是循环入口至 Present 返回的墙钟，包含等待、抽取/Prepare、录制、提交和驱动调用。分段计时有嵌套，工作线程 CPU 时间之和也不是并行录制的墙钟，不能相加推算整个 CPU 占用。分配量按相关线程采集，包含小量计时记录开销，不是进程所有线程的总分配量。

## CPU 场景结果

| 当前场景/配置 | 中位数 ms | 各轮 P95 范围 ms |
|---|---:|---:|
| 默认静态，hybrid，async 开 | 12.923 | 14.153–14.611 |
| 默认静态，hybrid，async 关 | 10.539 | 11.842–12.473 |
| 默认静态，硬件光栅，async 开 | 9.992 | 10.845–12.404 |
| 默认动态，hybrid，async 开 | 12.840 | 13.937–14.145 |
| 位移，hybrid，async 开 | 17.242 | 20.688–20.974 |
| 位移，hybrid，async 关 | 14.612 | 17.168–17.254 |
| 位移，硬件光栅，async 开 | 14.345 | 16.996–17.131 |
| 稀疏动态，hybrid，async 开 | 12.093 | 13.307–14.784 |

本机当前 hybrid 场景关闭 async 后默认场景快约 18.4%，位移场景快约 15.3%。这说明该设备和工作量下，多队列协调成本超过收益；它不是跨硬件关闭 async 的依据。本次保留显式开关，没有根据单机结果植入自动切换启发式。

历史默认静态 hybrid/async 为 43.444 ms，当前为 12.923 ms；无 async 历史为 39.726 ms，当前为 10.539 ms。这是整组修复后的历史对照，不能拆成各项修复的独立收益。默认 24 帧验证的候选、SW raster 和驻留页等主要几何计数可对应，但图像不是逐像素相同，历史第 100 帧 capture 还有右下区域缺失，当前捕获显示完整球阵；不把该对照称为同输出的隔离 A/B。

位移 fixture 由当前已有场景生成器重建，材质 shader 使用当前的硬件过滤采样版本；历史 fixture 用的是较旧的位移采样形式。当前验证为 16,740 patches、207 个达到质量限制、0 dropped，历史为 1,452 patches。因此不报告位移整帧的历史倍速。上表当前 async 开关比较使用同一个新 fixture。

默认静态 hybrid/async 的分段中位数：

| 分段 | ms 或 B/帧 | 解释 |
|---|---:|---|
| Cluster reconcile | 0.0014 ms | 无材质/结构修改时的入口 |

这些数据明确否定“总 CPU 已到 0.5–1 ms”或“稳态零分配”的结论。当前剩余成本集中在命令生成与后端提交、即时输入与绑定数据、资源状态提交，而不是把 0.0001 ms 的分析复用继续当作整体优化目标。

提交计时包围整个 `Backend.Submit`，原始 JSON 字段仍为采集时使用的 `nativeSubmitMs`。它并未单独计时 `ExecuteCommandLists`；后端还执行等待参数准备、命令引用处理、swapchain 检查、队列锁、Wait/Signal 和提交状态登记。3.672 ms 不能全部归因于显卡驱动，更不能视为不可优化的原生调用下限。队列 `Wait` 在 GPU 队列上建立等待，本身不等于 CPU 阻塞等待 GPU 完成。

## GPU 灯光结果

两组场景捕获第 100 帧，等待应用退出后各取 7 次 RenderDoc EventGPUDuration 回放。前后 cell 配置都是 80×45×16、每 cell 容量 64，默认为 1 directional+3 non-directional，位移场景为 1+1。

| GPU 事件 | 历史中位数 ms | 当前中位数 ms |
|---|---:|---:|
| 默认 BuildClusteredLightGrid | 2.676640 | 0.091136 |
| 大范围点光源 BuildClusteredLightGrid | 10.081216 | 0.315392 |
| 当前 ClearClusteredLightGrid，默认/位移 | — | 0.006048 / 0.006048 |

建表事件分别约为历史耗时的 1/29.4 和 1/32.0。当前默认热点转到 ClusterShade（0.469 ms）；位移的 24 次 ClusterTessellationSplit 事件合计中位数约 0.251 ms。灯光配置维度一致及独立 GPU readback 测试支持建表修复有效；这里不把整幅图像宣称为逐像素等价。

当前计数事件耗时之和为默认 1.665 ms、位移 1.733 ms；历史分别为 5.183 和 11.414 ms。**事件相加不能表示有队列重叠的实际 GPU 帧墙钟，不能倒数为 FPS，也不能与 CPU 帧循环相减。** 位移整帧工作量变化亦限制历史总和比较。完整七轮值、捕获路径和 shader entry 汇总在机器可读结果中。

## CRUD 规模复测与验证

复用历史外部探针的同一份源码，直接引用最终普通 Release 程序集，关闭分层编译。每个独立分支有一个 64 字节 buffer、一写一读两个 pass；只计 `BeginEdit + 修改 + Commit`，初始化和引用检查在计时外。每组 12 次预热、36 次采样、3 轮交替规模顺序，共 48 组。它不包含帧执行或 GPU 工作。

| Pass 数 | 单标签修改 μs | 增删一条顺序边 μs | 空提交 μs | 标签分配 B | 空提交分配 B |
|---:|---:|---:|---:|---:|---:|
| 64 | 2.2 | 5.5 | 1.4 | 5,576 | 4,240 |
| 256 | 2.5 | 5.8 | 1.3 | 5,672 | 4,240 |
| 1024 | 2.6 | 6.0 | 1.4 | 5,768 | 4,240 |
| 2048 | 2.6 | 5.8 | 1.3 | 5,816 | 4,240 |

2048 pass 的历史单标签修改为 1883.9 μs / 2,786,752 B，当前为 2.6 μs / 5,816 B；历史空提交为 974.3 μs / 1,259,304 B，当前为 1.3 μs / 4,240 B。重复设置同一标签当前约 1.4–1.5 μs / 4,240 B。全部样本保留远端无关 pass 和依赖时间线对象；标签、相同值和空提交均不增加结构版本，真实顺序编辑增加 1。

64–1024 pass 的第一轮仍有冷启动影响，部分操作为后两轮的数倍；2048 pass 标签三轮为 2.6、2.7、2.6 μs。表中是三轮中位数的中位数，原始范围均保留。不将微秒尾数当作跨机器保证。这个结果证明所测单点修改不再随无关图规模线性复制，并不代表其它类型修改均有相同复杂度；空提交也仍有固定分配。

构建命令为 `dotnet build SomeEngine.slnx -c Release --no-restore -t:Rebuild -m:1`，结果 0 警告、0 错误。普通解决方案测试命令为 `dotnet test SomeEngine.slnx -c Release --no-build --no-restore -m:1`：**2,742 通过、3 失败、1 跳过，不能称为全绿**。本次渲染相关结果：

- RenderGraph：Release 70/70，额外 Debug 81/81。
- Direct3D12：421 通过，1 项 Intel 硬件测试因本机不具备对应硬件跳过。
- Render.Cluster：139/139；Render：81/81；Assets：154/154；Runtime：13/13。
- 四组真实场景各运行 24 帧，开启 GPU validation 与输出验证：默认、位移、WPO/alpha、稀疏动态均成功。
- GPU readback 回归覆盖灯光 0/1/80 个灯、小/大覆盖、两个 view、容量溢出和有效索引；Buffer 部分读取；Texture 多 mip/layer 跨队列数据；别名顺序、生命周期编辑后分离、host-visible upload/readback 共存、空闲区合并及全空 heap 释放。

全量测试的三个额外失败是 `LifecycleClosureTests.WorldClosing_RejectsUnrelatedJobCallback`（异常类型）、`BufferJobAccessTests.WarmedBufferAdmission_DoesNotAllocatePerCallback` 和 `GeneratedContractTests.GeneratedPrimitiveAndSpanViewGettersAllocateZeroBytesAfterWarmup`（零分配断言）。序列化整组重跑 143/143 通过；生命周期测试在 ECS 整组重跑中通过。ECS 零分配测试单独运行通过，但 ECS 整组重跑仍为 310 通过、1 失败，关闭分层编译后依然失败，因而不能归因于 JIT 或宣称已解决。相关 ECS、Job、Serialization 的 253 个产品源文件与测量前 SHA-256 全部一致。本次未改这些模块或放宽断言，保留此项整组测试问题及首次失败日志。

## 证据位置与边界

原始测量、完整日志、独立插桩源码和运行副本位于 `F:/.codex/research/render-retained-delivery-20260905/`：`wall-time-summary.json`、`gpu-summary.json`、`crud-summary.json`、`final-product-hashes.json`。正式性能结果只使用 `delivered-*` CPU 数据；修复途中采集的旧轮次和失败日志保留作排错记录，不纳入最终矩阵。正常产品源码没有临时性能探针。
