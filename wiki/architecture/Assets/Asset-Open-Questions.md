> **重构范围说明（2026-09-12）。** [冻结原则](Asset-Rebuild-Principles.md)与[执行任务](Asset-Rebuild-Tasks.md)只替换本次明确讨论的设计。本页中与之冲突的段落待更新，未涉及的架构继续适用；历史验证仅代表当时结果。现有序列化与存储能力的保持依据见[源码审查](Asset-Serialization-Review.md)。

本页只记录尚未确定的设计和它造成的实施边界。已经确认的共享原则由 [[Asset-Sharing-and-Writes]] 维护，整体导航见 [[Asset-Files]]。更新本页、描述一种可能写法或发布进度都不构成用户确认。

## 嵌套写入的公开形式尚未确认

已确认的是逐层浅复制原则：独占则直接写，共享则浅复制当前节点并接回当前分支，下层引用继续共享。**如何从公共 API 表达一个嵌套节点的写入，尚未确认。**

这项未决设计涉及以下关系，而不仅是方法叫什么名字：

- 写入怎样定位当前资产分支和当前数据节点。
- 取得子对象后，后续修改怎样遵守共享隔离与结束边界。
- 集合元素和更深子节点怎样继续采用同一规则。
- 应用对象 `T` 的普通身份语义怎样保持，大型内容的读取者怎样被考虑。
- 第三方可变对象怎样明确适配，而不假定能接管任意赋值。

尚未确认必须生成访问对象，也未确认采用逐层 `WriteXxx` 入口。文档不会把其中一种写法标成默认，更不会把普通 C# 嵌套赋值解释成已经具备自动分离能力。

## 当前实现中的偏离

先前自行引入的整片不可变 record、`ImmutableList` 及 `init` 属性方案没有得到确认。这些代码尚在工作区中影响类型与调用方，不能因为它们存在就把它们记录成最终模型。

这种改动目前影响 ShaderMetadata、反射与材质元数据、ShaderRef、纹理 tile、Mesh 集合以及渲染资源组。导入器中原来的可变构建方式与这些类型发生编译冲突。具体类型的职责仍由 [[Asset-Shaders]]、[[Asset-Textures]]、[[Asset-Meshes]] 定义。

## 可以独立推进与被阻塞的工作

| 范围 | 当前边界 |
| --- | --- |
| 已确认的对象模型、基类职责、具体生成代码与显式文件操作 | 可以按既定方案迁移和验证 |
| 已有材质具体属性、字节分支、World ECS 保存加载 | 可以独立验证其公共行为 |
| 嵌套写入入口及其生成、嵌套集合调用方 | 等待方案确认，不能自行选型实施 |
| 被上述类型挡住的导入器、场景工具与完整测试 | 需要设计落地后重新编译和验证 |
| 完整迁移完成声明 | 必须等待全部必要构建、行为测试和 AOT 结果 |

已完成的独立验证不能证明被阻塞部分完成；当前具体结果集中在 [[Asset-Verification-2026-09-10]]。
