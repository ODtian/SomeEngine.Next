# 资产校验与行为验收

2026-09-16。测试验证公开行为与 API，不以私有实现拼写或生成源码文本代替结果。完整执行证据见 [本次验收](Asset-Verification-2026-09-16.md)。

## 校验边界

外部文件必须检查范围、长度、类型、schema、完整性和必要认证；公共根明确描述身份和 Block。签名包认证在对象解码和编码视图中一致。截断头、非法长度、损坏内容和不匹配身份不能泄漏为错误的业务对象。

已经由编译期或共同内部流程保证的不变量不重复扫描。可关闭的诊断使用统一验证设施；真正决定安全读取、预算或业务结果的检查保留。目录查询与 Block 存在性查询不夹带隐式导入、加载或全图业务验证。

一次导入检查生产者冲突、设置一致性和依赖环。失败结果不进入正式目录。创建使用对象之前，具体 Block 转换检查该类型真正需要的内容；它不要求通用 Asset 猜测所有扩展业务。

## 必须保留的行为

并发等待者相互独立取消；真实读取或执行完成前目标页不复用。缓存淘汰不破坏保留读者。分支首写隔离目标页和索引路径，批量可写期间不能重新共享。保存失败不替换有效目标，多输出失败按工程流程回退。已登记损坏产物可以重建，但不能覆盖另一个有效资产身份。

更新保留对象身份，并区分切换前失败与切换后通知或清理失败。旧内容清理不能误释放新资源。材质覆盖区分未填写、零值、空引用和重置，World 使用已有 ECS 引用编码和同一批实体。

## 验证层次

通用序列化测试保留协议、静态编码、分段接口、字段布局、包与签名、范围来源、预算调度、可选编码视图、原生布局及页生命周期。资产测试覆盖文本、二进制、未知 Block、按需取得、编辑保存、目录、来源配置、重新导入和全部资产家族。

外部消费程序集声明 Block 与 Importer，验证引用发现、Microsoft DI、替代生产者、强类型设置和编译期边界诊断。原生 AOT 必须实际发布并运行。模板必须在不含构建资产和缓存的独立目录从来源构建，应用必须使用自己的 Manifest，并验证多帧有实际几何及着色输出。

性能工具报告初始化和重复访问、分配与复制、实际底层保留、不同负载以及尾延迟，不在单元测试中以机器绝对耗时作为正确性断言。热路径零分配测试先完成初始化，但仍执行原访问断言，不能用预热掩盖每次发生的分配。

原始临时文件用后清理。测试和正式工具保留；Wiki 记录真实结果、日期、输入和平台限制，不把某个子集或未执行平台写成全量保证。
