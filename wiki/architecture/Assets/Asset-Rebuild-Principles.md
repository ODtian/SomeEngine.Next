# 资产重构：冻结概念与原则

设计基线始于 2026-09-12，本页包含 2026-09-16 的 Block / Importer 架构和 2026-09-29 的存储及 Shader 生命周期修订，规定当前应有行为。Shader 编译、反射和驻留的完整规则以 [Shader 总规范](../shader/Shader-Block-Residency-Refactor.md) 为准。按日期记录的交付结果见 [执行任务](Asset-Rebuild-Tasks.md) 与 [验证记录](Asset-Verification-2026-09-16.md)；当前实现及验收未关闭项见 [2026-09-29 审查](../../../reviews/AssetSpecReview-2026-09-29.md)。

本次范围包含全部现有资产接入，以及后续独立审查和成熟实现对比中确认的序列化缺陷、职责与 API 不足；统一在同一份执行任务中完成。

本文件收敛本次讨论涉及的资产设计变化。执行顺序、保持与修改范围和逐项验收见 [重构任务](Asset-Rebuild-Tasks.md)，现有底层能力的源码依据见 [序列化审查](Asset-Serialization-Review.md)。[资产架构导航](../Asset-Files.md) 是统一入口。

**只替换讨论中明确要改变的设计；未讨论的架构保持现状。** 上一版将此扩大成整个资产库、序列化容器、文件格式及资产包重写，现撤回。对于被替换的 Asset 模型，不加兼容外壳；沿用现有且不冲突的底层能力属于正常复用，不是兼容负担。

**所有现有资产都必须接入新体系。** 保持通用基础设施和业务算法，不意味着允许任何现有资产继续使用旧表示、旧加载或旧生成路径。资产迁移的覆盖必须完整，不能只完成新建样例或部分资源类型。

## 已确定的 Asset、Block 与导入边界

Asset 是身份、引用和生命周期单位；Block 是 Asset 内部开放、强类型的数据单位。同一语义 Asset 可包含多个正交 Block，由不同扩展和管线分别提供。Scene 引用 MeshAsset，不绑定 Cluster 或其他管线表示。

Block 自己决定表达、编解码和取得方式，可以是文本、二进制、外部描述、延迟数据或仅进程内的数据。Asset 不分文本资产或二进制资产，也不保证所有 Block 负载已经驻留。持久类型 ID 建立直接索引，查询和静态编解码适合 AOT，不以类型名称或反射扫描发现实现。

范围读取、压缩及真实操作预算继续服务文件 I/O；通用 CPU 页设施和每文件解码缓存已经移除。具体系统显式读取所需 Block 并创建自己的使用对象；业务分页表达取得单位，最终托管数据均由普通 GC 引用保活，未来流送仍通过明确的取得和发布完成。

Importer 是扩展提供的局部内容生产能力，直接消费原生来源库对象。多个 Importer 可以处理同一来源对象和同一目标 Asset，写不同 Block 并读取依赖结果。同一 Block 在一次结果中只能有一个生产者，由配置选择或冲突检查决定，不以覆盖顺序裁决。

项目引用确定可用能力。SG 发现扩展并生成 Microsoft DI 注册和编辑器能力描述，不生成完整流程或跨扩展业务逻辑。来源 `.meta` 保存实际选择、强类型参数及身份映射；单次覆盖不自动写回。衍生 `.import.json` 记录实际输入和已生成输出，不是人工身份的备用来源。

完整来源流程统一读取、遍历、维护语义身份、保存登记、失败清理和重新导入。Importer 只负责自己的转换和直接引用。每次导入的 Context 缓存执行结果，依赖调用和遍历复用同一结果，检查循环与生产者竞争，不要求固定执行顺序。

这些边界取代此前把业务字段直接放在 Asset 根、从使用对象镜像资产、纯静态手写扩展组装及固定单生产者链的设想；保留通用编码、文件范围读取和渲染算法。

## F01　重构范围与取舍规则

- 修改范围是已讨论的 Asset / T 区分、独立资产声明、公共读写 API、按数据语义选择 GC 对象或业务分页、资产源表示、身份与伴随信息、发现 / 目录 / 注册职责，以及这些变化必需的接入调整。
- 所有现有资产类型及其变体、组合资源、默认内容、导入输出、配置、World、工具与测试消费样例全部纳入。每类都要完成声明、引用、发现 / 登记、取得、适用的编辑分支、保存 / 构建以及创建 / 版本发布流程；不要求每类都实现页级 COW 或原地更新 T。
- 沿用静态编码、类型目录、根与语义块、范围 I/O、调度、预算、包、签名、差分、编码视图及原生布局证明的有效能力；调整已确认有问题的职责边界和公开入口，不按整库推倒处理。
- 独立审查确认的认证遗漏、共享预算等待、可写访问重新共享，以及标准缓冲区 API、可定位输出、共同打开流程、未知类型描述、字段排列和视图重复扫描，一并纳入正式交付；不能留作资产完成后的可选事项。
- 保持现有项目结构及未讨论的业务架构；不预设必须另建一套资产库或更换全部文件格式。业务类型反向依赖资产设施等已明确冲突，可以调整对应代码与项目引用。
- 被替换的 Asset 和序列化 API 不建立别名、转接外壳或双轨开关。未变化的底层能力继续使用，不为删除旧名称制造新实现；明确修正的协议部分更新版本与相关消费者，不保留双格式回退。
- 现有资产定义、默认内容与导入输出全部按新体系接入，并通过新流程构建和验证。真实业务内容、身份以及不冲突的底层编码规则可以延续，容器与包格式不必因此变化；不为旧资产 schema 增加迁移读取器或旧加载回退。
- ECS、图形设备、渲染图、Slang 编译能力和独立业务算法保持；只修改与上述明确变化有关的连接处。
- 每项删除或重写先说明：对应哪项已讨论变化、已有能力为何不能直接使用、具体冲突位置、最小修改范围及需要保持的公共行为。仅因文件位于 Assets 或 Serialization 目录中，不能成为删除理由。
- 每次新增抽象，先写出其独立数据、主要持有者、解决的问题及比现有公共类型更简单的理由。没有独立职责，就不新增类型或管理器。
- 遵循根 AGENTS.md 的命名、统一验证、测试范围和临时文件清理规则。

## F02　术语与职责

| 概念 | 定义与主要数据 | 明确边界 |
| --- | --- | --- |
| 源文件 | 人维护或外部工具生成的输入，如 Slang、图像和模型源文件 | 一个源文件可以产生零个或多个资产，不要求每个源文件都有资产身份 |
| 资产 | 可独立引用、保存和构建的一份内容，具有资产 ID | 资产不等同于文件、某个 CLR 对象或一个使用实例 |
| 资产定义文件 | 人维护的引擎原生内容，或明确描述如何构建资产的文件 | 可以引用多份源文件；拥有自己的身份 |
| Asset | 身份、引用、Block 索引及当前内容分支，提供共同资产操作 | 普通引用不承诺所有内容持续驻留 |
| Block | Asset 内部开放、强类型的数据、编解码、按需取得与直接引用 | 不另建页管理，不代替语义资产身份 |
| T | 执行实际业务行为的普通使用对象 | 有效期间，其已承诺可直接使用的数据及必需依赖不再需要引擎从下级存储读取 |
| 业务页 | Texture tile、Mesh 几何页等由业务定义的数据单位 | 通用 CPU 分配页、页引用计数或公共释放协议 |
| 内部缓冲 | 一次读取、解压、编码或上传实际需要的工作空间 | 已发布数据的长期存储协议 |
| 发现 | 检测来源中的新增、删除与变化，取得必要描述 | 不要求构造 Asset、T 或编译源码 |
| 登记 | 将一份明确的资产描述加入或更新目录 | 是目录更新行为，不需要单独的管理器 |
| 目录 | 某个工程或已选定资产集合中，ID 到条目的主数据及其派生查询 | 不持有业务对象、内容页或可执行的类型处理代码 |
| Manifest | 目录保存下来或随资产包携带的清单 | 可由目录组件直接读写，不维护第二份独立更新的目录 |
| 类型注册 | 文件中的资产类型标识到解释、编码及版本处理代码的映射 | 不登记具体资产实例，不等同于 C# 类名 |
| 格式与导入器注册 | 输入格式到识别、读取或转换能力的映射 | 扩展名不承担全部业务类型身份 |
| 存储 | 打开选定位置与内容版本的字节范围 | 不决定业务类型、不创建 T、不重新选择另一个版本 |
| 构建产物 | 根据主要来源和构建条件生成的内容 | 可以重建，不能成为第二份独立编辑的主要来源 |

核心流程为：

    源文件 / 资产定义
        → 发现、必要的导入与构建
        → 登记目录
        → 按 ID 选择条目和内容版本
        → 存储打开内容
        → 按类型解释为 Asset
        → 显式创建或更新 T
        → Game world → Rendering world

类型与导入能力在启动或工具接入时注册，不出现在逐字段、逐帧的数据解释路径中。

## F03　Asset 与 T 的区别是保证，不是命名

- T 有效期间，正常业务访问不执行引擎下级存储加载。必要的读取、转换、索引建立和依赖解析在创建完成前结束。
- 该保证覆盖 T 当前公开为可用的数据，不要求它装入整个源资产的所有平台、所有细节级别或所有未来流送内容。
- 未来流送内容由显式加载过程取得，再更新使用状态。T 的属性或普通业务方法不得暗中寻址资产文件。旧的“使用对象内部保留来源并继续读资产”的模式必须替换。
- Asset 的身份、内容版本和可定位的内容引用不因缓存淘汰失效；实际数据访问必须已有驻留保留，或先完成显式取得过程。
- Asset 恰好全部驻留时，仍然没有仅凭普通 Asset 引用就无限保留所有内容的保证。编辑不意味着内容天然无效，也不以“编辑中不能实例化”作为区分理由。
- T 自身不依赖资产加载、编辑和保存设施。资产侧知道怎样创建 T。代码直接创建 T 同样成立。
- 引擎保证自己提供的数据与流程；不能声称通过框架就证明任意用户代码永不执行 I/O。
- 普通托管数据通过强引用保活；需要本机地址的实际操作仅在自身期限内固定内存，不增加调用方保留或释放数据的协议。

## F04　类型、字段和对象身份

- 具体资产使用独立的 XXXAsset 类型。公共共同流程可以集中于不绑定 T 的 Asset 基类；不以旧的泛型基类和嵌套资产类型作为新模型。
- 资产类型与 T 允许多对多。一个资产可以创建多个 T；多个资产类型可以创建同一种 T。转换通过明确的强类型代码表达，不建立必须一对一的通用转换表。
- Asset 根只保存共同身份和 Block 描述；业务字段声明在 Block，T 字段按实际使用需求定义。二者可能重叠或不同，不能从 T 逐字段镜像出资产模型。
- 不生成每种业务类型的第二套字段根、编辑包装或访问包装。Block 是实际数据，不是另一份镜像；生成代码直接服务其声明和静态编码。现有通用只读编码视图没有另一份业务字段存储，继续保持，不按 Data / View 等名称误删真正的业务数据或公共能力。
- 不要求一个资产 ID 对应唯一 Asset CLR 对象；不为实现引用相等而增加全局资产对象缓存。不同访问者可以表示同一资产的不同内容版本或编辑分支。
- 同一 T 的普通引用保持 C# 引用语义。确有可变业务身份的类型可以显式更新已有 T；Shader 等不可变对象创建完整新实例，再交换消费方持有的外层引用。不同创建结果默认是不同使用实例，是否复用由明确的业务需求决定。

## F05　唯一主要持有者

| 数据 / 状态 | 主要持有者 |
| --- | --- |
| 当前编辑字段、集合与明确提供的不可变字节 | 对应 Block；Asset 协调所属分支的共同访问边界 |
| 可再次取得的最终数组与进行中的读取 | 统一 AssetByteCache：整数 LRU 记录、共享字节预算和临时读取任务表 |
| 使用中的最终托管数据强引用 | Texture、Mesh、Shader 等实际消费者；由 GC 管理可达性 |
| 文件句柄、解压工作空间与上传暂存 | 实际读取或上传操作；保持到对应操作完成 |
| 输入大小、在途工作及 GPU 的预算统计 | 对应操作和设备已有的预算设施，不统计全部 GC 存活数据的精确硬额度 |
| 资产 ID、位置、登记版本、已登记直接依赖 | 目录条目 |
| 路径查找、反向依赖、源输出查找 | 从目录或明确的源记录派生的索引 |
| 资产当前编辑内容中的引用 | 当前 Asset 内容；目录不反向覆盖它 |
| T 的业务状态和设备资源 | T 及其既有设备关联 |
| 来源身份、人工设置、需要保留的子资产身份映射 | 源伴随描述 |
| 编译依赖、摘要和产物缓存状态 | 构建记录 |

目录记录登记事实，Asset 和 Block 选择内容定义，使用对象持有业务数据。统一字节缓存按不可变来源、chunk 和范围复用最终数组，预算同时计入缓存数组及动态索引。

编码字节、解码后的托管数据、上传暂存和 GPU 内容可以是不同的必要表示，不因同时存在就判为重复主数据。预算各自约束实际操作；移除引用不代表 GC 立即归还内存。不再维护含义相同的第二份可写内容、读取调度器或预算账本。

## F06　最终存储与内部缓冲

- 普通字段使用 C# 值、对象和集合。整体生成、整体替换的数据使用实际长度的托管数组；已有独立不可变 GC 数据直接共享。
- 文件读取与解压直接写最终数组。外部借用或可覆写数据在逃逸前复制；不经过通用 CPU 页池。
- tile、mip、LOD、Mesh 几何页按业务单位取得。业务单位不要求固定内存页大小，也不引入页引用计数或 COW。
- 编码和上传的内部缓冲保持到实际操作结束，其释放协议不传播到托管使用对象。
- 小 Memory 切片会保活整个数组；必要时复制成独立的实际长度数组。连续分配确有问题时才考虑内部不可变分段，不设通用自动分页阈值。

## F07　共同数据定义与真实工作完成

- 多次创建通过不可变字节来源取得数据。未变分支及同一文件来源的 Retain 和 Loader 复用对应的缓存数组。
- 数组中的整数链接 LRU 记录强引用已缓存数据，所有语义共用一份预算；任务表仅在实际读取期间保留共同任务。使用对象通过普通强引用保留最终数据。
- 单个等待者取消只退出等待，不能取消其他等待者的共同读取。读取成功或失败后清除共同任务；失败允许重试。
- 实际 I/O 结束前来源和目标内存仍然有效。使用对象不为了保活字节而持有 Asset、Block 或文件。
- CPU 工作结束不代表 GPU 已结束读取；GPU 资源和上传内存遵循既有完成信号。

## F08　普通数据分支与不可变共享

- Duplicate 保留资产身份，复制需独立修改的字段和集合结构，共享不可变元素与未变数据定义。成本允许随集合结构大小增长。
- 字节修改创建完整新值，旧消费者继续持有旧值。Shader 代码整体生成和整体替换，不建设通用 COW。
- 不通过浅复制引用声称隔离任意可变 CLR 对象；不通过序列化往返或反射遍历实现 Duplicate。
- 细节规则由 [数据共享与修改](Asset-Sharing-and-Writes.md) 统一维护。

## F09　公共读写 API

- 普通属性赋值、集合元素赋值和不可变值替换是主要写法，不生成逐字段编辑包装。
- 数据交换使用 ReadOnlyMemory、ReadOnlySequence，操作内部使用 Span、Memory 和 IBufferWriter；没有配对释放托管数据视图的协议。
- ReadBytesAsync 明确取得所需字节。SetBytes 替换明确提供的不可变数据；调用后不修改其数组。借用数据先复制。
- 普通可变集合遵守 BCL 的并发使用规则。异步取得在第一次等待前固定输入，不在 getter/setter 隐藏 I/O。
- 保留静态类型编码器及共同文档读写能力，不维护第二份可变目录、分段链或读取调度器。

## F10　身份、路径与版本

- 资产 ID 表示长期身份；路径表示位置；内容版本表示某次内容；内容摘要用于缓存和完整性。这些事实不能互相代替。
- 持久化资产之间的引用以 ID 为准，可提供按路径查找的用户入口和诊断提示。ID 不匹配时不悄悄改用路径下的另一份资产。
- 移动、重命名和修改内容保留资产 ID。新建独立资产分配新 ID。
- Duplicate 默认创建同一资产的内容分支；另存为新资产通过明确操作产生新 ID，不把内存分支自动等同于新资产。
- 源文件可以拥有源 ID；导入输出依靠源身份及持久子资产键 / 映射保留身份，不能根据临时数组下标、源路径或内容摘要重新决定身份。
- 工程内无明确覆盖关系的重复 ID 是冲突。资产包覆盖使用明确的来源优先级，打开时遵守已经选定的条目与版本。
- 资产引用的类型限制针对资产类型或资产家族，不以 T 作为所有身份的泛型绑定。
- 沿用不冲突的类型身份计算、编号编码和严格 schema。字段排列或根类型描述确需改变时，在 B06 / B08 明确数据定义、版本与产物重建范围；不任意更换其他磁盘类型名、ID 编码或文件结构。

## F11　可读定义、二进制产物与大块内容

- 人维护的引擎原生定义默认可读：参数、引用、配置、曲线和结构内容支持审阅与差异合并。
- 图像、音频、几何负载和大规模采样不强行展开为文本。可读定义可以引用二进制大块。
- 高效加载继续使用现有二进制文档的分块、压缩和范围读取能力；编辑环境也可复用。新增可读前端，并修正现有后端的已知不足；必要协议调整在原容器基础上实施，不建立并行的新容器或包系统。
- 每份内容只有一个可编辑的主要来源。生成产物不接受独立编辑后再反写源内容的隐式流程。
- 文本和二进制围绕同一资产定义提供编码，不增加一套业务字段镜像类型。
- 文件块、纹理 tile、几何页是各自用途的单位，不能默认一一对应。通用文件写入代码计算本次排列、偏移和对齐。
- 保存沿用现有文档写入器的流式根编码和未修改来源块复用；使用标准托管内存或已有分段视图作为输入，不再实现一套同义写入器。
- 冷读和解压遵守存储边界。独立流送单元必须能够独立取得、解码和校验；保存小改动不得加载所有无关块。
- 引用共享不自动提供跨独立文件的磁盘去重。普通另存文件不承诺只写出修改范围；需要共享块存储时作为明确的存储能力实施。

## F12　元数据与文件命名

| 信息 | 主要保存位置 |
| --- | --- |
| 原生资产 ID、资产类型、格式版本、内容属性与资产引用 | 原生资产定义自身 |
| 外部源身份、人工导入设置、必须保留的输出身份对应关系 | 源伴随描述 |
| 大块内容及解释该内容所必需的块描述 | 资产内容或其明确引用的二进制块 |
| 可搜索摘要、反向依赖、缩略图、实际编译依赖与缓存状态 | 可重建目录或构建记录 |

- 真正一对一的伴随文件使用“源文件完整名称 + .meta”，与源文件同目录，如 Ground.png.meta；追加后缀，不替换原扩展名。
- 保留源文件完整大小写。一个源文件最多一份该类伴随描述；伴随文件不再产生自己的伴随文件。
- 编辑器移动、重命名、复制时成组处理源及伴随文件。重命名保留身份；复制为独立资产时明确分配新身份。
- 严格一对一关系由命名推导，不把同一源路径作为另一份可独立修改的状态重复保存。
- 独立资产定义按自己的名称和格式扩展名命名，如 Surface.shader；其中明确记录源码选择，不能根据同名自动绑定 Surface.slang。
- 原生资产自身已有身份和设置时，不增加 .shader.meta 等重复描述。
- 外部来源的人维护信息保存在 `.meta`；衍生构建记录使用完整名称追加 `.import.json`。原生 `.shader` 的衍生记录也使用 `.shader.import.json`，它不重复保存人工身份与选择，不属于第二份人工伴随描述。删除或损坏衍生记录只触发重新构建。
- 扩展名帮助识别用途与格式，文件中的类型标识确认业务含义。目录不把伴随文件再次发现成一个业务资产。
- 元数据可单独读取不要求单独文件。公共描述区域与二进制文件头都可以提供低成本发现能力。

## F13　目录、发现与类型注册

- 目录主数据是一份 ID 到资产条目的映射；条目保存必要类型、位置、登记版本、来源关系及已登记直接依赖。其他查找由主数据派生。
- 来源、资产与依赖一起保存在 `Library/AssetManifest/catalog.json`；不再导出或回读三份旧索引。目录替换期间已有读者保留旧完整内容，新读者取得新完整内容。普通项目查询不从进程当前目录、父目录或引擎旧产物回退。
- 目录描述最近一次登记的内容。未保存编辑由 Asset 分支持有；不得让目录用旧值覆盖当前编辑。
- 目录查询不触发扫描、导入、编译、Asset 打开或 T 创建。
- 编辑环境通过明确的发现与变更过程更新目录。发行环境读取已构建的清单和资产包，不依赖开发目录扫描或导入器。
- 原生定义、源身份信息和包目录足以重建必要目录；目录文件不是资产 ID 的唯一存放地点。
- 类型未安装时，只要公共描述格式可识别，仍可列出资产 ID、类型和位置；使用时再报告缺少处理能力。
- 类型注册与具体资产登记独立。沿用现有 BinaryContractCatalog 的二进制类型身份与静态编码注册；资产类型创建能力、文本格式或导入器只补充各自缺失的信息，不另建同义注册表。文件类型标识不直接等同于 C# 完整类名；重命名代码不改变磁盘类型身份。
- 使用静态声明、生成代码及明确注册接入处理能力。禁止每字段操作表、运行时反射图扫描或按 object 类型袋推导行为。
- 不要求所有资产只能创建一个 T，不用类型注册建立这种隐含限制。

## F14　三种依赖与显式状态变化

- 构建依赖：哪些源文件、工具版本与选项变化后需要重建产物。
- 资产引用：当前资产内容直接引用哪些其他资产；目录记录的是最近登记版本的这项信息。
- 使用依赖：创建 T 后实际保留的对象、数据和设备资源。
- 三者分别维护各自事实，不能把编译源文件、内容 ID 和已加载对象混成一张无含义的图。
- 资产引用可以形成共享图，不能把所有引用都当作必须立即递归加载的内容。创建 T 所需的依赖范围由明确的转换代码决定；无法构造的必需循环在该边界报错，不因目录中存在循环引用就禁止发现和保存。
- 保存成功先产生完整且可打开的新内容，再把返回描述登记到目录；失败或取消不能登记半成品。中间被打断时通过重新发现 / 登记恢复，不在属性写入中偷偷保存目录。
- 当前文件被原子替换后，已有读取者仍读取其选择的旧内容，不能在一次读取中拼接新旧版本。
- 如果外部来源已不能提供选中的版本，读取必须明确失败，不能悄悄改读新版本；已经完整取得数据的有效 T 不受这类来源变化影响。
- 创建使用对象失败时，本次尚未发布的普通托管内容自然离开作用域，明确拥有的临时页或设备资源按其局部协议清理。新版本在成功交换前失败则旧引用保持不变；交换成功后不能因通知失败破坏新状态。不可变 `Shader` 创建新实例，不原地更新也不向上传播释放。
- 旧 GPU 内容的延迟释放仍由现有使用完成机制处理，不新增资产专用提交通路。

## F15　Slang 源码和着色器资产

- .slang 保持原文和原生语言规则；源码内部使用 Slang 的导入名称、路径与包含规则，不改写为资产 ID。
- 一个源码文件可以没有入口、包含多个入口，或与其他源码一起参与编译。发现源码不自动创建一个 Shader 资产。
- 需要独立引用的着色器定义使用可读 .shader 文件，保存资产 ID 和 ShaderSourceBlock.SourceNames 指定的根源码组合。当前来源 schema 不保存入口选择、target 或特化设置。
- .shader 可以引用多份源码，多份 .shader 可以复用同一源码。它是独立资产定义，不是严格一对一伴随文件。
- 不默认再创建 .slang.meta；只有存在独立的源文件级身份或人工设置时才需要，且不得复制 .shader 中已有的信息。
- 根源码中的入口、阶段、线程组和其他源码已有声明由 Slang 发现；当前编译行为按 Slang 顺序组成所有声明入口。target、profile、编译选项和特化由构建工具或业务调用边界提供，使用 Slang 的 SessionDesc、TargetDesc 和 SpecializationArg，不在资产中另建同义字段。
- Slang 编译依赖依据编译器报告或实际文件读取获取；不以正则搜索模拟语言依赖规则。
- 项目根目录和外部库搜索路径由调用方明确提供；不通过寻找上级工程标记或当前工作目录推断。已知输入不变时仍核验真实输出文件的内容摘要和文档版本，不能只信缓存记录。
- 构建键覆盖源码及传递依赖、编译器 / 工具链版本、入口组合、特化、目标能力、编译选项及影响解析的搜索配置。缓存键不等同于资产 ID。
- 可复用 Slang 的预编译能力，分别缓存前端结果与目标代码。编译产物和同次生成的必要描述保持版本一致。
- 已返回的 Shader T 不在普通使用过程中再读取源码或完成必要编译。需要另一目标或新特化时，显式创建新的完整 Shader，再在消费边界交换引用。
- 编译失败保留仍在使用的旧内容；发行可以使用预构建结果，用户机器上的显式 Slang 编译也是正式路径。

## F16　用户扩展与限制

- 用户 Asset 遵守本文件的加载、编辑、共享和保存语义；普通字段与数据使用标准托管类型，可再次取得的字节使用统一预算缓存和共同读取规则。
- 用户定义内容、编码与业务转换；T 保持普通业务对象形态，不要求统一 T 基类、逐类型数据视图或反向资产引用。
- 使用行为的公开接口接收 T；导入、编辑、保存等资产操作接收 Asset。不能把“任何用户函数都不许接收 Asset”作为可实现的保证。
- 不提供资产到 T 的隐式转换或属性触发的隐式实例化。
- 程序集依赖应支持“资产代码依赖业务类型，业务类型仅依赖所属业务库和通用内存设施”；移除业务类型对资产设施的反向依赖。
- 对明确登记为使用对象或使用接口的边界，编译期检查直接或经静态成员类型包含 Asset / AssetRef，以及调用加载、编辑、保存接口的违规依赖。
- 检查范围必须有明确角色，不把整个游戏工程禁止引用资产库；不通过方法名白名单猜测任意算法的职责。
- 外部程序集应能增加原生资产类型与导入器，并通过显式强类型方法创建多个 T；新增一种资产不需要修改引擎的中心类型分支。
- 类型注册、编码和边界检查须支持 Native AOT，不依赖开发工具已扫描过所有业务对象。

## F17　领域行为与渲染边界

- 材质继承区分未覆盖、显式零、显式空引用和重置覆盖；覆盖事实不能通过“值是否等于默认值”推断。父链和类型相容性在明确的解析边界处理。
- 字段是否被覆盖是材质内容本身的业务数据，可以按字段保存；它不是逐字段 COW 计数，不能与页共享状态混为一谈。
- Texture 的维度、层、面、mip、tile，Mesh 的几何范围、空间索引与负载解释，以及 Shader 的业务描述和编译算法继续保持。Texture/Mesh 的业务分页不能反推 Shader 或所有 Asset 使用页级 COW；仅替换与已讨论 Asset / 使用对象边界冲突的表示或包装，未讨论的布局与业务数据不因重构自动作废。
- 延迟取得纹理 tile、几何范围或其他后端代码的行为放在资产 / 显式加载侧；已经可用的 T 不再充当潜在磁盘来源包装。
- World 继续使用实际 ECS World、组件与拓扑，不建立固定 SceneData 图或第二种 World 来绕开现有 ECS。
- 世界持久化通过明确注册的组件和拓扑编码，以及明确的资产引用解释接入。不能把任意 GUID 当资产引用，也不能反射整个 T 图来推导资产。
- 渲染数据仅通过 Game world 到 Rendering world 的既有路径进入。流送和内容更新先进入明确的使用状态，再沿该路径更新渲染。
- 引擎不默认顶点属性布局。具体导入编码和用户材质 / shader 的解释相配合；不把某个导入器布局升级为通用管线前提。
- 不在渲染路径逐字段读取元数据进行动态多态；不因资产重建增加资产直接提交 GPU、另一个几何对象通路或另一套 GPU 生命周期。

## F18　验证、证据与允许调整的参数

- 测试覆盖公共 API 与可观察行为。保留现有静态编码、文件协议、严格 schema、范围来源、调度与预算、包签名 / 差分、编码视图、原生布局和 AOT 回归要求。公共头大小、字节编码或生成诊断的测试可以是合法公共行为测试，不能统称为旧实现细节。
- 已明确调整的 Asset / 序列化 API 或协议更新对应行为测试；未变化部分的回归要求保持。删除只约束私有结构或生成源码内部拼写的测试，不能批量删除或跳过测试掩盖回归。
- 编译成功不等于生命周期正确；至少验证并发取得、取消、失败、淘汰、分支、已取得视图、保存后重新发现、更新及延迟释放。
- 独立验证编辑期源格式、构建产物、外部扩展、Native AOT 和实际应用 / 渲染接入，不能用一个标量页实验宣称整个资产系统已完成。
- 完成条件包括现有资产接入清单全部关闭；生产、工具、默认内容和测试样例均不得继续依赖旧资产体系。通用能力回归与资产迁移完整性分别验收。
- 序列化审查中的全部问题也必须逐项关闭；已有 149 个测试通过只作为当时基线，不替代新增认证、预算、写访问、分段输入输出和生成行为验证。
- 优先识别内部已形成的不变量。可关闭的诊断走统一验证设施；真正影响功能的边界错误仍必须处理，不能因关闭诊断而出现悬空数据或写坏内容。
- 性能验证覆盖用户实际访问路径、分配量、复制量和尾延迟，不写依赖机器绝对耗时的脆弱单元测试。
- 临时脚本、探针、运行目录和原始结果用完即删；保留有明确用途的正式测试与文档证据。

## F19　序列化职责与公共 API

- 数据编码负责字段读写、类型描述、静态生成、读取限制和可选编码视图；文档容器负责根 / 块、压缩、偏移、完整性、认证与保存。
- 内容存取负责来源、范围读取、解压和单次读取限制；资产体系负责资产身份、目录、导入、构建、资产包组织、编辑及创建使用对象。同一数据定义负责复用存活结果和进行中的读取，文件层不保留长期解码缓存。发布对象由普通 GC 可达性保活，不为层数机械新增项目或管理器。
- 编码器通过标准缓冲区接口访问数据，不依赖通用页管理、资产、GPU 预算或逐帧使用状态。通用生成器不再调用资产生成器注入声明。
- 公共 API 提供统一编码入口、每类型静态读写、基础读写器三个使用层次。支持固定 Span 输出、IBufferWriter 输出，以及连续和 ReadOnlySequence 输入；单段快路径保留。
- 文档输出要求可写且可定位的 Stream，沿用回填目录和流式摘要；不以 FileStream 的具体类型代替实际能力要求。
- 明确每个入口是否分配、复制、保留输入或缓冲完整内容；异步名称不构成有界流式保证。分段编码不能先拼接整份输入或输出再声称完成适配。
- 文档解码不因来源保留压缩内存或映射就被禁止；借用输入、写入调用方目标和必要解码结果各有明确使用期限与预算。压缩 / 解码 / 上传 / GPU 的必要表示不被误判为多份主数据。
- 实际操作预算按工作完成归还额度并唤醒等待者。业务流送限制选取的工作，不以淘汰仍在使用的托管数组作为继续读取的前提，也不要求使用方手动 Trim 或释放数据视图。

## F20　共同文档打开与明确根类型

- 对象解码与编码视图共用必要的文档解析、边界、来源版本及认证规则。读取策略可以不同，认证能力不能随入口变化。
- 来自签名包的资产在使用根内容前必须与包中已认证的描述匹配；内部摘要自洽不代表通过外部认证。
- 公共描述读取不调用业务编码器，也不要求调用方预先知道业务 T；文档必须能明确指出根类型，不能从一个可能含多个条目的类型目录中猜测。
- 类型未安装时仍可列出公共描述；实际解码或建立视图时再核对预期类型、schema 和处理能力。
- B08 若证明当前协议无法无歧义表达根类型，则补充最小根类型标识并明确版本；沿用其余有效容器与包机制，更新全部相关消费者和测试。

## F21　字段布局与编码视图

- 字段身份和编码排列由明确的数据声明决定，不由 partial 源码文件路径、文件重命名或文件移动决定。B06 落实可检查的字段身份 / 顺序规则与冲突诊断。
- 严格 schema 与明确字段身份分别成立；不因确定字段顺序就引入任意版本兼容或逐字段动态分派。
- 已验证且保证使用期间不变的编码视图，访问后置字段不重新扫描前面的整个集合或字符串。固定布局采用直接偏移，可变布局复用首次解析得到的必要定位信息。
- 偏移索引只是读取辅助信息，不持有另一份业务字段内容；序列化视图保持可选，不要求 Asset / T 新增逐类型访问或编辑包装。
- 边界、安全性和使用期限检查继续成立。可关闭的重复诊断走统一验证设施，不能把必要认证和输入边界检查当成可选优化关闭。

## 补充冻结：项目模板中的材质与 Shader 组合

2026-09-12：用户通过侧边讨论同步的最终结论适用于本次完整重构，覆盖 A22、A23、A26、A29、A30 和 A33。

- Standard、Unlit 等具体默认材质作为新项目模板内容分发。创建项目后即为普通用户代码和资产，用户可修改、替换或删除；引擎不自动补回或覆盖。“官方”仅表示模板来源。
- 模板成套提供强类型 C# 材质声明、独立资产声明、顶层 Slang 源码、独立 Shader 定义和默认内容。C# 进入普通用户 csproj，按职责分入业务库与资产扩展库，不引入脚本资产，也不要求每个材质独立工程。引擎保留 Material 基类、生成器、通用编码 / 资源设施和可复用 Shader 算法及管线入口。
- 引擎 Shader 库作为只读 include 依赖分发。顶层项目 Shader 负责组合材质算法与管线入口，同一个 Shader 可提供多组入口，同一个 Material 的 Shader 引用保持不变。不得加入管线局部 Shader 替换表、全局适配表、自动回退或按具体材质类名推导实现。更换 Material.Shader 表示更换材质实现。
- 审查并拆清 standard.slang 对 Cluster 的直接包含、资源访问及最终输出耦合，使外部入口可以复用材质算法；不规定统一顶点布局，不增加 Game world → Rendering world 以外的数据通路。
- .slang 保持原生源码和 include 规则；可读 .shader 持有独立身份和 SourceNames 指定的根源码组合，入口由 Slang 发现，编译设置由明确调用边界提供。不增加组合语言或重复登记，不默认添加与 .shader 重复的 .slang.meta。发布可以只提供构建产物，其中保存的 Slang 数据支持用户机器显式取得直接反射和编译结果。
- 项目 Shader 修改后重建同一身份，材质引用不变。落实外部 Shader 库搜索路径、可移植依赖追踪、模板首次无缓存构建、用户生成 / 编码接入和明确类型身份；依赖更新不能静默重写模板实例。
