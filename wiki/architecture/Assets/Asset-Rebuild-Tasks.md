# 资产重构：保持范围、修改范围与执行任务

日期：2026-09-12。设计依据：[冻结概念与原则](Asset-Rebuild-Principles.md)。已有能力依据：[序列化源码审查](Asset-Serialization-Review.md)。

**当前完成的是统一范围、设计原则与任务拆分；以下实现任务均未执行。** 用户已将独立序列化审查及成熟实现对比中确认的不足全部纳入本次资产重构。A00–A33 与 B00–B08 共 43 个任务构成同一执行清单；B 编号表示新增的通用能力修正，按依赖执行。

**资产接入范围覆盖全部现有资产。** 下文的“保持”针对通用能力、真实业务数据与算法，不允许某个现有资产继续留在旧体系。已有资产类型、变体、组合资源、默认内容、导入结果、工具和测试消费样例都必须完成接入。

## 执行规则

1. 每项改动先列明讨论依据、现有可用能力、实际冲突和最小修改范围，再实施。已审查并纳入的问题必须修正，没有具体冲突证据的其他区域保持现状。
2. 以现有项目和公共能力为起点；先验证 Asset / T 与分页 API 的外部用法，再修改相应实现。不得先复制一套通用基础设施。
3. 开始时记录工作区已有修改，不使用 reset、整目录覆盖或清理未跟踪文件处理它们。用户要求重构不等于允许误删其他工作。
4. 全部现有 Asset 接入新体系，不加兼容外壳、旧资产回退或双轨开关；明确改动以外的编码 API、文件结构和业务行为继续保持；B06 / B08 必要协议变化同步更新所有消费者。修正全部资产消费者是任务内容，不能将整个解决方案失去回归要求当作默认前提。
5. 替代完成后删除对应冲突代码；A32 核对残留。删除必须有实际调用范围和替代依据，不能以目录、类名或“旧”字作判断。
6. 每项任务只有明确交付物、前置条件和公共验收；实现过程中发现范围过大时继续拆分，不连带重写无关职责。
7. 勾选任务前记录实际完成的验收。既有序列化、范围来源、调度、包和业务测试是应保持的回归依据；不能批量删除来让新实现通过。
8. 临时实验用完立即删除；有明确用途的正式消费样例、行为测试和构建检查保留。
9. 新发现若要求改变未讨论架构，先补充具体矛盾并修订原则与任务，不能悄悄扩大执行范围。

## G1　通用页与内存访问

### B02　修复共享预算下的淘汰与唤醒

- [ ] 前置：B00。
- 交付：统一考虑局部额度与共享账本压力的分配 / 淘汰判断；明确跨使用者的可回收内容与通知，确保等待请求能继续推进。
- 验收：总额度 4、外部占用 2、无活跃使用的缓存占用 2 时，再请求 2 可自动淘汰后完成，不依赖手动 Trim；多个调度使用者共享预算时有同样保证。
- 并发验收：取消一个等待者不影响其他请求；释放、失败或取消消除阻塞后能唤醒请求；活跃内容不被提前释放；各项账本无重复占用或泄漏。

### B03　分离来源能力与内存使用策略

- [ ] 前置：B00、B01。
- 交付：保留范围来源接口，移除文档层仅因来源保留内存 / 映射就禁止合法解码的规则；明确借用、读入目标和解码结果的使用期间。
- 验收：同一压缩 / 未压缩块由文件、内存、映射及可用的远端范围来源读取时内容一致；不具备不可变借用保证的来源可走明确的调用方目标读取；版本变化、校验与预算仍有效。
- 约束：必要的压缩输入与解码结果分别计入预算，不增加隐藏完整副本；不能把借用期间和池化内容回收期限混为一谈。

## 必须优先暴露的风险

- **语法与 COW 冲突**：若完整元素赋值 / 通用批量写仍需要逐类型访问视图，A01 / A08 就应失败，不能等到材质接入再补包装。
- **共享根漏判**：便宜复制索引根后，不能只检查叶页直接引用计数；在 A07 / A08 验证。
- **小页拖住大竞技场**：长期小切片导致空间保留，在 A11 测量并限制分组或转交方式。
- **现有流送 T 不满足保证**：Texture、Mesh、Shader 的后续 I/O 必须移到明确取得流程，在 A24 / A25 / A28 验收，不能改名后照搬。
- **文本与二进制双主数据**：只允许一个可编辑来源，派生产物可删后重建，在 A12 / A21 验证。
- **目录早于内容成功**：生成内容与目录切换按完整版本推进，在 A15 / A17 / A20 验证。
- **生成器重复字段知识**：外部消费与不同编码都使用同一声明，A14 和 A30 通过公开行为证明，不能生成第三套业务数据模型。
- **分段与压缩接入**：现有块读写以连续 Memory 为主；在 A10 / A13 验证页适配及冷读放大，不暗中复制整份内容，也不据此改写容器格式。
- **修正遗漏**：不能只完成资产新样例，而把 D01–D10 留到之后；A31 / A33 按问题与资产两份覆盖表验收。
- **范围失控**：在统一处理已讨论不足的同时，A00 / A32 仍检查有效能力的复用；未涉及的 Slang 编译、领域算法、ECS 和渲染架构保持。

## 完成的定义

完成需要同时满足：新 Asset 语义端到端可用，所有现有资产及其消费者完成接入，全部默认内容经新流程从源构建，关键边界有公共行为证据，外部用户与实际应用已接入；D01–D10 全部关闭，旧资产和被替换的序列化路径没有兼容残留，未讨论的架构与有效公共能力继续保持。
