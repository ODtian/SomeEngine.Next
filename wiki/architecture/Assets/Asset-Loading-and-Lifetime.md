# 资产取得、对象创建与生命周期

2026-09-30。打开 Asset、取得 Block、创建使用对象和发布新版本是不同的操作。对象关系见 [Asset 与 Block](Asset-Objects.md)，文件规则见 [文件读写](Asset-File-IO.md)。

## 打开不等于全部驻留

具体 `MeshAsset.OpenAsync` 或 `TextureAsset.OpenAsync` 通过共同文件入口取得身份和 Block 描述，并按类型需要取得小型元数据。大型负载和其他扩展的 Block 可以继续未加载。`ContainsBlock<T>()` 查询存在性，`GetBlock<T>()` 仅访问已取得的内容，`GetBlockAsync<T>()` 明确承担异步取得。

一个 Block 内部还可以包含冷负载和外部来源。因此 Block 对象存在也不是全部字节驻留的保证。同步字段访问不会为调用方隐藏文件读取。

Loader 按资产 ID 和存储所选版本合并文件打开，缓存文档而不是解码负载、唯一 Asset 或使用对象。调用方取得独立保留的文件访问，分别创建自己的内容分支；同一来源可以建立多个互不依赖关闭顺序的对象。存储回调和关闭操作在共同缓存锁之外执行。

统一 AssetByteCache 按不可变来源、chunk 和范围复用最终数组与进行中的读取；Loader 保留的同一文件来源采用相同字节键。详细规则见 [数据共享与修改](Asset-Sharing-and-Writes.md)。

## 使用对象的保证

具体系统请求认识的 Block，异步完成自己需要的读取、解码和资源创建。返回的对象直接持有当前已承诺可用的数据，不再调用 Asset 异步访问模型。关闭 Asset、Loader 或可淘汰缓存，不破坏已创建对象的数据。

该保证不规定一种统一 backing。普通不可变值使用独立 GC 对象或数组；Slang 结果由 `Shader` 直接持有 Slang 接口；Texture tile 和 Mesh 几何页同样持有独立托管数据，业务分页不带入 CPU 页生命周期。池、arena、映射或可关闭来源若不属于发布对象的业务生命周期，必须在异步创建边界内物化为独立最终数据，不能把临时保留协议泄漏给调用方。

该保证不要求一次创建取得所有后端或全部细节级别。Texture 可先具备基础 mip，Mesh 先具备必要空间索引和最低细节几何页。后续内容通过明确的资产侧取得和业务流送机制形成可用数据，再发布完整状态；渲染准备只消费就绪内容。

## 取消、失败与释放

| 事件 | 可观察的行为 |
| --- | --- |
| 一个并发等待者取消 | 结束该等待，不取消其他等待者共享的读取或 Importer 执行 |
| 取得失败 | 清理本次未交付内容，错误可观察，修复来源后允许重新请求 |
| 已加载数据无人使用 | 统一预算通过整数 LRU 保留数组；淘汰或 Clear 解除缓存引用后由普通 GC 可达性决定回收 |
| Asset 关闭 | 拒绝新操作，等待其实际取得结束，释放自己的 Block 和来源 |
| Loader 关闭 | 结束自身读取和缓存，不销毁借入存储或已创建使用对象 |
| Context 关闭 | 取消并等待本次执行结束，清理未转交结果和相关作用域 |
| 使用对象不再被引用 | 普通 GC 数据自然回收，不要求调用方配对释放 |
| 持有原生设备对象或业务流送保留的对象关闭 | 只释放它明确拥有的原生资源或业务保留，不把关闭协议传播给纯托管子对象 |

取消请求不是实际工作结束。即使某个来源不能即时取消，目标内存和来源也必须保留到真实读取停止。结束允许使用期间后继续保存 Span 或 Memory，并不能阻止池复用；需要自由保留的数据应明确复制。

## 显式发布新版本

版本切换发生在已经负责保存当前对象引用的消费边界。读取、解析或资源创建在交换前失败或取消，旧引用继续可用；新对象完全建立后一次替换外层引用，读者不能观察逐字段更新的中间状态。

`Shader` 是不可变 GC 对象，每个版本都是另一个完整实例，不提供 `Update` 或 `Dispose`。Material、Texture、Mesh 只有在其自身业务确实需要可变身份、流送页或设备资源时才保留对应更新/关闭边界；不能从其中一个类型反推出所有使用对象都应原地更新或实现 `IDisposable`。旧帧通过普通托管引用和既有 GPU 队列完成关系保留旧版本。没有资产专用的全局 GPU 等待或旁路提交。文件监听、普通属性和 Dispose 不自动保存或更新对象。
