# Asset CPU 字节缓存

## 存储与索引

应用的 Asset 字节取得共用一个 AssetByteCache 和一个 CPU 字节保留预算，默认 512 MiB。Texture tile、Mesh 页和 BVH、已保存的 Shader 字节使用同一池，不按类型或文件预分固定份额。应用可以明确提供同一个缓存实例配置预算；直接文件打开使用进程共享实例。文件句柄和编码根缓存、实际 I/O 和设备预算仍由原有设施管理。

缓存主体是一组可复用的结构体数组记录。每条记录含数据键、最终 byte[] 的强引用以及 Previous、Next 两个整数数组下标；键到记录下标使用 Dictionary。整数链接仍维护 LRU 顺序，但没有逐条节点 class、对象引用链接或命中时分配。新增、淘汰与复用在同一缓存锁内维护一个索引和一份字节统计。

文件数据键包含选定不可变文件来源的身份、存储 chunk key、范围起点和长度。来源身份随共享文件内容建立并由 Retain 复用；相同来源绑定同一文件版本。独立打开的不同来源分别完成字节校验。完整 chunk 与范围不能混淆；相同起点的不同范围也不能混淆。共享的是同一份不可变字节来源，不是唯一 Asset 对象或仅以 AssetId、路径、业务页号建立的语义去重。不同文件版本、编辑分支新值彼此隔离；未修改内容继续指向原来源。

缓存记录随实际缓存的单位增长，不按所有声明 tile 或页数建立引用节点。记录空位通过整数复用；Clear 解除记录和索引的保留。来源不为了字节保活被缓存持有，缓存键不包含文件句柄、Asset 或 Block 对象。

## 预算与淘汰

预算计入最终数据数组的对象头、对齐和缓存索引数组的保留空间。固定协调对象、源描述、在途读取及消费者自身保留不属于可淘汰数据预算；不能把它解释为整个 GC 堆的硬上限。索引容量与数据保留均应可报告。

预算不足时，从 LRU 最久未使用端撤销缓存强引用并复用记录。数据单位超过可用缓存容量时仍正常返回读取结果，不加入缓存。淘汰不调用数据消费者的 Dispose，不修改已返回数组，不报告 GC 已立即归还内存。

消费者持有普通 byte[] 或 ReadOnlyMemory。缓存淘汰后，这些引用继续有效；后续新取得可以重新读取，缓存不承诺找到仍被外部引用但已淘汰的数组。未保存、不能重新取得的唯一字节仍由 Block 作为主要内容持有，不受缓存淘汰控制。

## 共同读取

进行中的读取放在缓存级的临时键到任务表，仅未命中时创建任务，完成或失败后移除。已经完成的任务不作为长期字节保留。不同调用者请求同一键时共享一次实际读取；一个等待者取消只退出自己的等待。

实际读取在缓存锁外执行，并在第一次等待前保留来源，保持到 I/O、解码 Job 和最终结果交付完成。未压缩输入直接读入最终实际长度数组；Brotli 编码输入保存一份实际长度字节，Job 将其解压到最终数组。单块读取限额、共享资产解码类别的在途与执行配额及最终数组缓存预算分别由原持有者维护。清空缓存不取消正在被调用者使用的读取；清空前开始的读取完成后不重新建立旧缓存保留。

已有业务对象的普通数据访问继续直接读取它持有的数据。缓存仅参与 Asset 侧明确的取得，不能把哈希查找、LRU 维护或文件读取放进 T 的普通 getter、Rendering world 的正常使用路径。

## 验收

- 通过公开资产接口验证不同版本与不同范围隔离、同来源复用和实际读取次数。
- 清空、预算淘汰、关闭 Asset 或 Loader 后，消费者已经持有的数组仍可读。
- 并发等待、单个取消、读取失败重试及实际来源寿命符合共同读取规则。
- 预算包含动态索引和数组分配费用；超预算单位成功交付但不缓存。
- 基准同时统计命中、淘汰、重读、索引空间和分配，不把整数链接称为消除了链表，也不声称与普通引用零额外成本。

缓存的读取输入是保存实际文件、chunk 或几何范围的数据结构，沿 `IAssetByteRead.ReadAsync` 直接完成读取。`AssetBlockSource` 使用文件读取数据，`MeshPayloadSource` 使用自己的实际范围数据；等待取消作用于共享读取的等待者，读取结果继续保持最终托管数组。
