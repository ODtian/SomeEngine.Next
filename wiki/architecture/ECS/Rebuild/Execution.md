# 操作顺序与引用寿命

分析时间：2026-10-22 22:50 +08:00。状态：D算法方案；顺序回放、索引 Set、遍历结束后执行结构命令已于本轮确认。

分析方法：将公开入口拆成一次身份定位、一次容量准备、主值修改、必要派生维护和完成；对照现有组件、命令、关系与存档路径，逐项确定跨存储调用的参数和费用归属。

公开 `World.Add<T>` 保留已有 API 的重复添加失败语义，并保留原值；`World.Remove<T>` 在组件缺失时报告操作失败。内部已持有行与列的维护入口按对应存储操作处理，公共 API 的使用错误由实际类型存在性判断。

## 执行规则

| 入口 | 调用者持有的数据 | 执行与完成 |
|---|---|---|
| 普通值读写 | 当前 World、Entity；或查询已经绑定的行 | 普通值提供只读/可写 ref；取得追踪类型的写 ref 时登记该行版本 |
| 索引值 Set | Entity、新值 | 从Membership定位旧组、计算新key一次，准备目标容量，写主值并维护成员 |
| 结构操作 | 当前 World、Entity、组件组合 | 在结构范围内完成创建、迁移、删除和索引维护 |
| 行、Chunk、索引、邻接遍历 | 一个显式读取范围 | 该范围固定行位置、成员和列数组；结构命令在范围结束后回放 |
| 并行工作 | 已完成绑定的范围数组、访问声明 | 整批持有读取范围；Job 完成后释放，再进行结构回放 |
| 顺序 Playback | producer 顺序、命令头、typed 载荷 | 按顺序提交；失败保留已完成前缀，具体进度见 [[Commands]] |
| 原子回放 | 显式要求整批成功的调用者 | 在独立 World 上回放，成功后由调用者接收结果，成本见 [[Commands]] |

查询和成员视图的读取范围覆盖其 ref/span 的完整使用期。随机 Read/Get 返回的引用在调用者下一次可能改变该存储的结构操作前使用完毕；Job 中的随机引用处于整批访问范围内。普通组件的值写在已声明的写访问内执行；索引成员、启用位、表布局及邻接成员的改变属于结构操作。范围外的这些操作即时执行。缓冲元素 span 在同一缓冲的 Resize/Insert/Remove/Clear 或实体迁移前使用完毕。

公开入口读取执行连接一次并取得所需访问，验证外部Entity一次，随后传递已经解析的record ref、Chunk、row与列项。容量准备可能替换数组的操作，先完成 Reserve，再取得实际数组/ref。Core 的方法实际修改自己持有的数据；World 组合跨存储步骤。

## 一次操作的完整顺序

以下每行是设计中的通用执行路径，方括号表示按类型声明或已建立功能加入的步骤。版本规则由 [[Changes]] 持有。

| 操作 | 容量准备与输入读取 | 主值与派生修改 | 完成 |
|---|---|---|---|
| Create | 绑定最终类型及实际GroupBy键组合；Reserve 实体、目标行与已开启索引 | 取 ID；写最终行身份/值；[Shared行编号与成员、初始化 Buffer、启用位、版本、索引、Sparse] | 写 EntityRecord、Count 和批次结构版本；返回身份 |
| 已有列Set | 普通值取得值写访问；索引/Shared/受控拓扑取得结构写访问；定位一次并准备实际容量 | 写值并沿用启用位；[登记版本、旧组摘除/新组挂入] | 返回时主值与活动索引成员一致 |
| Add/Remove 组合 | 定位源行；一次取得到最终布局的边；Reserve 目标；[保留移除值、定位旧索引组] | 复制共有值并转移容器；写新增值；维护实际增删的索引；补源洞 | 修正被移动实体记录；写目标记录；发布本次结构变化 |
| Enable/Disable | 定位启用列；首次Disable准备EnableGroup<T>最终组合与位数组；[索引成员容量] | 首次迁移后重绑行，改一位及禁用计数；[移除/加入值索引、登记组件变化] | 保留组件值并发布状态；后续切换复用已有布局 |
| Destroy | 读旧身份/行；[准备保留的移除事实] | [按旧值摘索引、处理保留组件、释放 Buffer、清 Sparse]；尾行或填洞；追加销毁事实 | 普通Destroy完成已注册关系的局部清理再回收身份；DestroyDeferred由Maintain完成，见[[Relations]] |
| Clone/Prefab | 绑定最终表；Reserve；建立目标身份集合 | 普通值复制、Buffer 独立复制、启用状态、[Sparse]；完成 Entity 引用重映射 | 建立索引与目标版本；拓扑按所选复制范围维护 |
| ReadWorld | 读类型清单/身份/表形状，分配最终数组 | 解码各份主值一次；完成引用处理；建立 Sparse 映射、Shared 归并和拓扑 | 完成所有即时派生数据后返回 World |
| Restore | 完成现有工作与引用范围；预留容量 | 释放被替换的容器；恢复主数组/身份；按恢复模式处理版本与事实 | 推进 World 数据代数；重建依赖旧身份/位置的缓存 |

## 迁移、填洞与释放

迁移边只记录共有列的复制与状态转移。Add/Remove 的实际新增、释放与索引变更由该操作提供。相同实体的共有索引成员按 Entity 持有，其位置继续有效；只有 key 或成员资格变化时更新。

Buffer 在迁移与填洞中转移行内引用或溢出引用。源尾行的引用清空属于移交后的清理；容器回收发生在该值真实删除时。Clone/Capture 使用独立元素复制。含普通托管引用的 T 使用类型化赋值和实际写屏障。

填洞顺序是末行实体/共有值/启用状态/行版本搬入洞位，再修被移动实体的 Row。摘要按搬入行的已有版本提高上界；该移动保留组件的 Added/Written 版本。实体记录随最后位置写一次。

保留移除旧值的类型由 [[Changes]] 的 Removed<T> 路径处理。普通销毁的 ReleaseKinds 为 0 时直接执行基础 X；实际具有索引、容器、追踪保留或托管清理的表，按其紧密操作列表执行。这个表级位集合来自类型声明，服务销毁的单次能力分派。

## 跨功能费用只计一次

| 已取得输入 | 内部调用继续接收 | 计数归属 |
|---|---|---|
| record ref、源 Chunk、row | 值列、索引、Sparse、迁移 | 公开入口承担 R；内部复用身份与行位置 |
| 结构范围 | 创建/迁移/销毁内核 | 整个公开批次承担 G 一次 |
| 已绑定目标 Chunk、迁移边 | 目标追加、共有值复制 | 实际边定位由调用者计；分组使用已找到的目标，Shared编号随行转移 |
| 已取得旧值和Membership/group ref | Removed保存、索引摘除 | 旧值由Core持有，旧key由KeyGroup持有；Set计算新key一次 |
| 两端数组及步骤数组 | 连续同类迁移段 | 段外绑定一次；每行保留实际元素访问 |
| 已绑定变化结构 | 逐行版本写、词/块摘要 | 变化目录定位在绑定处计；每词/块首次更新见 [[Changes]] |

M(k)是包含G和边定位的迁移主体，公开入口再加E一次。GroupBy已取得目标时，组合本页内部阶段并复用目标。Shared按行编号和成员目录维护，其主存储顺序见[[Shared]]。跨页预算采用“E/实际访问 + 已发生的定位 + MoveKnown + 实际增删功能”。

## 批量合并规则

批次预留实体和目标行容量一次；同一列的连续值用 Fill/Copy；同源表、同目标表的连续迁移段复用边与列基址；整表销毁遍历实际资源/索引/Sparse 后一次发布 Count。任意实体集合的删除通过当前 EntityRecord 取得位置，或对已经确定的同 Chunk 行号按降序执行。

顺序命令按原命令流形成连续段。容量预留、类型绑定和相同内核的循环展开保持命令顺序。key 计算、关系基数检查、可见版本和失败位置随原命令发生。

## Clear、Dispose 与恢复

Clear 在工作完成和引用范围结束后遍历实际容器/保留事实，归还 Buffer，清已开启的值索引、Sparse 与拓扑，递增已用实体代数并重建空闲链。保留表对象和可复用容量，Count 归零；查询的表匹配仍有效。销毁消费者按批次收到原实体身份，或由调用 Clear 的 Relationships 同步清空并推进自身进度。

重建空闲链时绑定一次Records首项ref，按已用编号倒序更新各16 B记录的空Chunk、下一空闲编号和Generation。链头在局部变量中累积，记录完成后一次发布到World._free，随后发布空实体数量；各记录的代际递增和最终复用顺序沿原有规则完成。

Dispose 在相同完成点释放 World 持有的数组、资源与观察者；类型注册属于进程，保持自己的生命期。Restore/ReadWorld 的身份代数、引用处理和保留事实规则由 [[Serialization]] 持有。缓存以其实际依赖失效：列数组在每次范围开始时重取，表匹配依赖表集合，模板跨 World 绑定依赖 World 数据代数，存档绑定依赖类型注册版本。

可复用清理与最终释放各按自己的持有期执行：Clear清除拓扑Applied、邻接、claim等有效数组并保留容量，Dispose完成拥有值和独立邻接内容的释放后交还数组引用。Sparse最终释放逐项执行值操作，再把Store的Values、Entities、Pages与Changes置空，既有查询持有的同一Store随Count归零成为空结果。Buffer整列释放已清除的header由该列操作完成一次，带Presence的列继续清理整段中的托管引用。

按实体编号组织的Applied、邻接、claim及值索引Membership沿World.Used+1的历史身份上界清理，各数组以自身实际长度限定范围。退休数据仍按独立目录完整释放，哈希桶与分组数组沿各自编号域处理。Core.ClearLifecycle在所有服务清理后统一清销毁事件并Reset观察位置；恢复入口由各SavedData.Restore还原自身观察进度。

## 范围与批次释放顺序

普通值Set复用值访问，结构变化复用结构访问，具体分支及引用持有者由[[Implementation]]定义。内部S表示结构写组合；单独普通值写采用SetCore。

Clear先取得结构写并结束现有工作，按服务清派生数据与进度，再由Core释放主列中的实际容器，最后发布空实体集合。Children的主数组由Core释放，关系服务释放其独立Applied、差额索引和旧代数据。Sparse/索引/查询的类型存储对象按World寿命保持，Clear重置其有效内容，Restore在同一对象上替换数组并重建。查询在下一范围重新绑定数组，既有类型存储引用继续指向该对象。Dispose完成最后一次释放并结束这些对象的寿命。

Clear、Dispose及恢复前的旧值释放按实际Chunk和拥有值的列调用一次ComponentType.ReleaseRows，在闭合类型内绑定整列span。整列存在时直接按行释放；带Presence的列沿实际存在位释放。自定义IComponentOperations<T>继续按原行序收到各值，Buffer的内部IComponentColumnOperations<T>复用同一列范围执行池归还或整列引用清空。实体代数、索引、变化事实、观察者进度和Job完成仍沿上述统一完成顺序处理。

WorldExecution.OpenStructure/OpenValues返回本次实际持有的WorldAccess回执。WorldJobs沿既有HasStructureWrite判断当前结构写权限：嵌套结构、普通值及资源操作继承外层写访问时返回空回执，由外层统一结束访问；独立操作的回执持有实际访问并在Dispose时结束。原有类型借用和查询借用继续以Enter/Exit配对保持整个ref/span使用期，访问声明、Job深度和世界使用计数由同一个WorldJobs持有。
