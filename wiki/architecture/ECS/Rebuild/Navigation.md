# AGENTS目录结构与渐进式阅读

AGENTS.md承担所在目录的导航和局部约束，算法与布局由专题页持有。根级原则、领域事实、目录导航各有一个维护位置。

| 层级 | 文件职责 | 进入下一层的条件 |
|---|---|---|
| 仓库根 | 通用命名、验证、测试与领域入口 | 确定工作领域后进入对应项目 |
| 领域索引 | 项目路径、主数据、依赖方向及专题入口 | 按本次行为选择一个或几个项目 |
| 项目AGENTS | 本层数据、允许依赖、公开入口/消费者、目录到专题的映射 | 修改某个存储或执行阶段时读取对应专题 |
| 子目录AGENTS | 实际子目录的局部入口和上级链接 | 该子目录形成独立维护范围时建立 |
| 技术专题 | 具体字段、算法、顺序、成本和完成边界 | 实施选中的路径时读取实现、调用者和行为测试 |

实际入口为[仓库目录索引](../../../../docs/agents/index.md)。ECS项目、Systems、SourceGen、Serialization、Job及比较项目分别有短AGENTS。Relationships目标程序集建立时承接当前Core中Hierarchy/Relations目录的导航；导航随实现文件迁移到其所属目录。

项目AGENTS使用下面的统一形状：一段说明主数据与依赖；一张“本层入口／对应专题／消费者”表；一段指向上级规则和本层行为测试。已有上级规则通过链接引用，专题算法在其原页面维护。

按需阅读顺序为根AGENTS → 目录索引 → 所选项目AGENTS → 对应专题 → 实现/调用者/行为测试。跨层动作继续沿专题给出的消费者链接读取。完整重构从[[Implementation]]选择批次，再读取该批次的专题与[[Acceptance]]相应行。

目录创建与拆分时，维护父级索引和本层入口；算法改变时维护对应专题；通用原则改变时维护其原有原则页面。ADR依用户确认的决策流程维护。
