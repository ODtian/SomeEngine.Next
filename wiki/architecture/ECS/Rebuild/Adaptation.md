# 等价适配与逐路径判定

分析时间：2026-10-22 22:50 +08:00。状态：E* 为独立适配设计；S-E 为固定版本的实际公共入口。

分析方法：先写明适配器自己保存什么、调用哪一个原生入口、何时维护；然后把“共同适配数据操作”和“两个不同 Core 的成本”分别相加。E* 与 D 相同的数据算法只表示该子过程相同。

全部参照的版本、能力分组与实际性能门槛由[[Acceptance]]持有。下文E*具体展开EasyEcs适配；其它参照逐行采用相同能力定义，并使用各自实际原生入口。源码计数沿各页固定提交，机器比较沿固定包版本。

## 适配入口和身份

E* 包装一个 EasyEcs.World，自己持有 SharedValues、SparseStores、完整 edge/Hierarchy 派生数据、CommandBuffer 和存档扩展。公开输入使用所属 World 的 EntityId；需要原生实体操作时通过 TryGetEntity 取得该实体句柄，再调用原生方法。适配层结构范围保护自己的数组；原生方法各自的 Structural 仍按调用次数计费。

仅校验身份的 R_E = World.IsAlive(EntityId) =〈2,2,3,0,0〉；需要输出原生句柄的 TryGetEntity 再写调用方结果一次。D 的 R=〈1,1,2,0,0〉。Source 的原生 Get/Set/Destroy 本身已经包括其身份检查；只有适配确实先校验再调用原生入口时才加额外 R_E。

适配类型 ID 与目录为 int，按实际编号增长。EasyEcs 原生组件编号宽度是 ushort；原生组件集合在其可表达范围内进行 S-E 对照，更大类型集合使用完整 int 类型目录的 E* 存储实现，并标为适配预算。类型宽度变化的清零、序列和元数据字节按实际宽度保留。

## 各能力的独立适配

| 能力 | E* 主数据与派生数据 | E* 实际 Core 调用 | 首次/增长/回收 |
|---|---|---|---|
| Buffer 默认对象 | 原生 DynamicBuffer<T> | 原生 Read/Get、原生缓冲操作 | 原生池、数组扩容与 Clone；追踪按同配置 |
| 行内 Buffer | h 项行内值与溢出数组，持有者为适配组件 | 原生实体定位/Set/迁移；适配类型化搬移/复制 | h 相同；溢出增长/旧引用清理均入账 |
| Shared | 外部 SharedValues<T> 唯一持有 T；原生列保存 SharedId<T> 整数 | SharedId<T> 实现 IGroup，以编号分表；Set/Remove/Read 调用原生列入口 | Intern/桶增长与 D 同能力；原生每行额外保存4 B共享编号，分组表建立用原生 GroupBy |
| 普通值索引 | 使用原生ValueIndex；旧key在Node | 原生Set、Find、Remove、Destroy | 原生Node/字典/留洞成员/有序key维护 |
| Enableable完整访问 | 原生Stored<T>保存唯一T，DisabledState<T>标签表达禁用 | Has/Read访问Stored<T>；Enable/Disable移除/添加标签；Set替换Stored<T>并沿用标签 | 查询翻译为Stored<T>加活动/禁用条件；实际标签首次/增长/位操作分别计费 |
| Sparse | 外部8 B分页cell、紧密 EntityId/T、12 B附着链 | 校验身份用 R_E；纯侧存储操作使用适配数组；包装 Destroy 先清附着再调用原生 Destroy | 真实使用页、值数组、附着目录与销毁注册均独立维护 |
| 完整关系 | 原生edge持endpoints/payload；外部邻接、Applied和声明的Claim/Pair占用 | 创建/修改/删除调用原生Create/Set/Destroy；最终校验与D同算法 | 所有邻接/占用/销毁序列及原生结构入口分别计费 |
| Hierarchy | 原生Parent/Children组件、外部AppliedParent与差额目标索引 | 原生列Read/Set/Remove；森林检查、原生Added/Changed/Removed | 同样即时/延迟维护、局部顺序、普通销毁与旧代身份 |
| 延迟命令 | 20 B头、typed载荷、批次结果对象及Created/Offsets、已用类型目录 | 顺序解码后调用实际原生操作；纯侧存储调用适配方法 | 记录/解码算法可相同；每条原生操作的 G 与身份检查继续发生 |
| 同步/异步 Job | E* 生成原生查询范围，提交同一 SomeEngine.Job | 工作体调用原生固定结构遍历或已绑定列 | 同一后端的队列、依赖、资源、异常与回收；范围生成按各自源路径 |
| 完整存档 | 原生 Core 数据段，加 Shared/Sparse/资源/拓扑策略等扩展段 | 原生 Save/Load 或已公开的批量列入口；扩展段走相同 codec | 原生临时 Rows/恢复复制保留；扩展数组直接建立；最后重建完整派生数据 |

Shared 适配保存的是共享编号，真实 T 始终在 SharedValues 一份。以普通逐行 T 的 GroupBy 为参照时，只比较分组能力；本表的 SharedId 适配用于唯一共享值能力。Shared Read 的 E* 前缀为原生 Read<SharedId<T>> + 类型存储 T + Values P1/A1，D 为其 Shared 列项/编号入口。

Enableable适配始终从Stored<T>访问保留值，活动查询排除DisabledState<T>，禁用查询要求该标签。已有标签列时Enable/Disable分别执行原生标签Remove/Set；首次Disable加入标签的迁移和构造。开启Written时通过Stored<T>的原生写访问登记同一版本；Added及保留移除值使用对应E*扩展。Enableable和值索引组合使用[[Indexes]]的活动成员侧索引，随标签变化摘挂；普通索引行继续采用原生ValueIndex。这样保留值、Has、活动成员与生命周期分别对应相同能力，其实际原生调用和侧存储费用完整相加。

Sparse 纯侧存储完整操作的 E* = G*（写时）+ T + R_E + SFind + 实际稠密/附着操作。与 D 的同一侧存储布局相比，身份前缀增加〈1,1,1,0,0〉。包装 Destroy 的总式为侧存储清理 + 原生 Destroy + 适配销毁事实，原生 Destroy 已含的身份/结构入口保留。

## 建立与重建的共同观察点

| 操作 | 比较开始 | 比较结束 | 两侧共同输入 |
|---|---|---|---|
| 首次关系/Sparse/索引注册 | 服务首次使用 | 已有实体均可通过新入口查询 | 同一实体集合/主值/身份 |
| 新表与查询缓存 | 新表尚未出现 | 新表建立且相关查询各打开一次 | 同一类型集合与查询条件 |
| Destroy或DestroyDeferred+Maintain | 原实体及拓扑可见 | 全部指定消费者完成清理 | 两种入口分别比较；相同销毁顺序/局部顺序/代数 |
| Clone/Prefab | 源与模板已给出 | 目标值、独立缓冲、索引和引用可用 | 同一复制集合与外部引用规则 |
| 全量读取 | 相同有效输入内容 | 返回可查询的完整 World | 相同 codec、保留能力与引用规则 |
| 后台保存 | 调用方请求该时刻内容 | 保存工作与输出提交完成 | 同样隔离的主值、同一输出服务 |

完整存档采用相同字段 codec 和内容；Core 容器、附加元数据和临时复制按实际路径计费。以不同分段格式比较时分别列实际输出字节，格式包装由各自实现承担。

## 逐路径判定方法

每条路径分别比较 P/A/B/W/L、实际读写字节、用户 key/codec 调用数、原子/锁、首次分配和保留容量。只有这些量在同一输入下逐项满足要求时记为“逐维满足”。增加功能使用相同 E* 能力后重算。

| 路径组 | 本轮可确定的结论 | 决定后续实现的约束 |
|---|---|---|
| 基础随机读写、复用创建、尾行销毁 | [[Storage-and-Queries]] 的D预算在所列输入下逐维≤对应S-E计数 | 实现按给定局部引用与整项写顺序展开；完整能力另加实际功能 |
| 批量创建、整表释放、POD填洞 | [[Bulk-and-Copy]] 的列出路径减少记录/基址重复访问 | 相同值/不同值、尾段/任意洞分别采用对应内核 |
| 缓存边与查询追加 | 边命中减少一次源字段读取；查询累计追加从二次复制变为线性复制 | 首次可见点包含所有实际查询刷新 |
| 变化登记 | 普通Changed三个子内核的D预算逐维≤对应S-E计数 | 完整入口加入写版本取得、Added、旧值保留和并行摘要完成 |
| Sparse/完整关系 | 共同侧数据明确相同，身份与 Core 操作按上表独立相加 | 分页、保序、旧代与祖先检查保留实际代价 |
| 索引Set | Membership指向KeyGroup；每次GetKey1，旧组直接定位 | 8I B反向目录、每不同key一份投影；有序组号每步额外一次组定位 |
| Shared Intern | 主值一份，专用桶/链接减少重复 T | 实际 c/e、值 hash/equals 和每行 SharedId 差额全部保留 |
| Job 同步调度 | 专用同步批次减少通用状态；后端队列/唤醒是剩余实际常数 | 同一采样配置、排队票寿命与完整完成点 |
| 完整保存/恢复 | 列绑定与最终数组填充减少逐值分派和中间复制 | 相同 codec/文件服务下合计完整复制与重建 |

“逐维满足”和“实际吞吐”分别回答源级工作量与机器执行效果；实现后在这些具体能力组上各做对应的最小行为与性能比较。

本轮完成的算法设计包括：列布局加一位Enableable；组号反向索引与一次GetKey；最终父链/占用校验；Job分阶段访问、缓存发布、词摘要合并与epoch回收。源码比较覆盖固定EasyEcs版本列出的路径，D/E*分别作为实现预算。逐维成本包含8I B索引反查、声明的12I B约束角色、32U B列目录、资源登记及实际用户计算；吞吐结论由相同能力和输入的实现比较给出。

类型范围按实际位置目录构造和维护计费，点访问按实体记录/列定位计费。比较使用Acceptance定义的首次与共同就绪点；原生提前维护和按需构造均归各自实际发生阶段。公开DeferredEntity按批次结果对象保留成功身份，Clear/Dispose后的Resolve及同批记录检查在各参照适配中一致执行。

只读Buffer使用只读视图，可写Buffer使用持有写访问的视图；Scope、身份检查和同批次并发规则按所比较能力完整提供。原生入口自带的能力先复用，实际差额通过其适配数据和公开调用补齐。
