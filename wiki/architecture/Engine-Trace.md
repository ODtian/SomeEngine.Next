# 引擎 Trace 基础设施

引擎的统一插桩入口为 `SomeEngine.Diagnostics.EngineTrace`。它只记录原始区间、帧标记、因果关联和计数；聚合、成本分析及未来的图形界面属于独立工具。当前 `tools/SomeEngine.Trace` 提供无头读取和分析，不向引擎增加性能阈值或评测标准。

采集端使用原生 C# 实现，不通过 Tracy 或 EventPipe 转发插桩事件。统计采样继续使用 `.nettrace` 链路。插桩得到的是线程经过时间，包含调度和阻塞；不能把它直接称为 CPU 忙碌时间。

## 记录路径

- `TraceSite` 在静态字段中声明，标签只登记一次，热路径使用数字标识。
- 每线程保留独立的嵌套信息与当前事件块；返回调用方的作用域只包含记录器引用和区间标识。
- 固定容量的预分配缓冲池通过 BCL 有界队列向独立写盘线程传递完整块。记录线程不等待磁盘。
- 缓冲不足或嵌套/标识容量不足会留下明确的丢失数量，不把不完整数据作为完整成本结果。
- 关闭采集时停止接收新事件、交出各线程剩余块，再完成文件。游戏工作不由采集器调度或延后。

## 归账

执行父区间与因果来源分别记录。主线程在等待中帮助执行别的帧产生的 Job 时，其实际调用嵌套仍用于独占耗时计算，工作归属仍指向原始帧。跨线程工作不会被误当作同线程子调用扣除。

无头分析分别输出帧延迟、主线程独占成本、工作线程经过时间，以及归属工作落在帧区间之外的时间。先检查全记录完整性，再选择预热之后的测量帧。独占均值可用于相加；各部分的中位数不可相加解释整帧。

渲染测量使用应用自身的 `--synchronous-frames` 模式时，当帧更新、提取和 GPU 完成等待都在当帧执行。等待采用完成事件，避免人为的窗口轮询周期。确定性场景回放属于应用输入，与通用采集器分离。

## 使用

命令、API 示例、格式及限制见 [SomeEngine.Trace README](../../tools/SomeEngine.Trace/README.md)。

采集框架不以某个 RG/RHI 优化假设定义事件，也不依赖某份性能报告。成本报告从原始 trace 派生，并需要同时报告插桩开销、工作负载和数据完整性。未来类似 Tracy 的界面可使用同一份原始数据；当前没有 GUI。
