# Streaming Failure

页面失败按原因区分。已经认证为无效的内容与来源暂时不可读不是同一种失败。

## 当前策略

- 认证、页格式或解码校验失败（InvalidPayload）进入该页的终止失败状态，不因后续缺页反馈反复读取同一坏内容。永久容量失败等不可完成的页请求也进入终止失败集合。
- 来源读取失败（SourceReadFailed）不永久拉黑该页。失败后释放本次读取与暂存资源，后续缺页反馈或可见需求可以重新请求，因此瞬时 I/O 故障恢复后仍能细化。
- 停止流送时的读取取消属于关闭流程，不把取消当作坏页或另起重试。

这一区分来自 2026-09-09 的 [渲染交付记录 B36](../Render-Delivery-2026-09-09.md)：把所有读取失败永久拉黑是当时明确修复的缺陷。对应提交为 `4b87345c648254bd73fa6b1ff2255677e9710b22`。本页原先“不可读取页一律终止”的文字来自更早设计，未随该修复更新。

## Invariants

- 当前最低有效 Bootstrap 继续保持可用时，细节失败只意味着暂时或永久无法进一步细化；不撤销已经有效的粗层覆盖。
- 恢复经过后续请求、读取、驻留发布和 GPU 使用边界，不建立 same-frame recovery path。
- 读取失败不得永久占住一次性的读取并发名额或页堆暂存范围；关闭必须取消并等待在途读取后释放它仍使用的来源。

## 仍需明确的策略边界

当前普通来源异常没有“瞬时 / 永久 I/O”分类。持续出现相同 SourceReadFailed 时，后续可见需求或缺页反馈仍可以再次触发读取；并发与字节预算限制同时进行的工作，但不是重试次数上限或退避策略。

因此不能将“坏内容不无限重试”解释为“所有 IOException 都应永久拉黑”。是否为持续来源故障增加分类、重试上限或退避，需要独立确定恢复条件与兼容性；本页的修正不引入这些新策略。
