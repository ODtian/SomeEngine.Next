# 姿势动画规格

状态：已确定（2026-10-03）。动画核心与属性动画见 ADR 0014 与 Wiki [Animation](../wiki/architecture/Animation.md)。本规格发布为 GitHub Issue #94，任务票为 #95–#110（标题前缀 `[Pose NN]`）。

## Problem Statement

引擎目标列出了动画系统（压缩、混合、蒙皮、physics control、IK），目前都没有实现。现状：
- GLB 导入器能识别 `JOINTS`/`WEIGHTS` 顶点属性；
- cluster 渲染只有 Deform 的设计（Deform compatibility 与 Deform cache 的 Wiki 页），还没有代码。

角色动画需要在大量实例上每帧求值，要求压缩片段、按骨骼数组批量混合、骨骼遮罩与状态机，并且要和界面、游戏使用的属性动画共用同一套时间、层、图与扩展模型，而不是另起一套。

## Solution

在引擎动画核心（时间线、值运算、动画层、图与融合）之上，增加"姿势动画"数据形态：

| 部分 | 内容 |
|---|---|
| 资产 | 骨架、动画片段（编码后的逐骨骼曲线、事件、根运动）、骨骼遮罩，均为 Asset Block，由 Importer 生产 |
| 压缩 | 参考 ACL 的默认编码器；编码与解码是可替换的算法接口，按 Importer 架构由项目通过 DI 提供 |
| 求值 | 每个角色在 Job 中按图采样片段，按骨骼遮罩批量混合，按动画层合成，从局部空间传播到模型空间，生成蒙皮矩阵 |
| 渲染 | 蒙皮矩阵经提取进入 Rendering world，由 GPU 蒙皮 Deform 实现写入 cluster 的 Deform cache |

## User Stories

1. 作为游戏开发者，我希望导入 GLB 中的骨架、蒙皮与动画，以便角色直接在引擎中播放。
2. 作为游戏开发者，我希望片段在导入时被压缩、运行时按时间采样，以便上千个角色占用可控的内存。
3. 作为技术美术，我希望按片段设置压缩误差阈值，以便在质量与体积之间取舍。
4. 作为引擎扩展者，我希望通过实现编码与解码接口并由项目 DI 提供来替换压缩算法，以便使用自己的方案，而不需要修改引擎。
5. 作为游戏开发者，我希望用 `Blend1D`/`Blend2D` 按速度和方向混合移动动画。
6. 作为游戏开发者，我希望用状态机在 idle、walk、run 之间按条件过渡并交叉淡入。
7. 作为游戏开发者，我希望用带骨骼遮罩的覆盖层让上半身独立动画。
8. 作为游戏开发者，我希望用叠加层叠加呼吸与受击动画，并且层权重本身可以被动画。
9. 作为游戏开发者，我希望通过写 `GraphParameters` 驱动图。
10. 作为游戏开发者，我希望动画事件（脚步、出手帧）以计数形式被读取，而不使用回调。
11. 作为游戏开发者，我希望得到每帧的根运动增量，由自己的移动系统决定如何应用。
12. 作为游戏开发者，我希望把武器等挂点按需暴露为实体。
12a. 作为游戏开发者，我希望有双骨骼 IK 与注视作为后处理阶段，以便手脚和头部指向目标。
13. 作为游戏开发者，我希望能通过公开的只读接口读取任意角色的模型空间姿势及其版本，以便将来做命中检测等用途。
14. 作为游戏开发者，我希望远处或不可见的角色降低更新频率，并在帧间插值。
15. 作为界面开发者，我希望界面中的角色预览使用同一套动画。
16. 作为扩展开发者，我希望自定义图节点和后处理阶段与内置的地位相同。
17. 作为渲染开发者，我希望蒙皮作为 Deform 实现接入 cluster 渲染，只处理可见 cluster。
18. 作为渲染开发者，我希望蒙皮矩阵沿既有提取路径进入 Rendering world。
19. 作为性能负责人，我希望姿势混合使用按骨骼数组的 SIMD 批量运算，并在 Job 中并行求值。
20. 作为性能负责人，我希望稳态求值不产生托管分配。
21. 作为引擎维护者，我希望姿势动画只依赖动画核心的公开 API，核心中不出现"骨骼"的概念。
22. 作为引擎维护者，我希望整个子系统兼容 NativeAOT。

## Implementation Decisions

- **程序集：**
  - `SomeEngine.Animation.Pose`：运行时；
  - `SomeEngine.Animation.Pose.Importers`：导入与编码，遵循 Importer 架构；
  - GPU 蒙皮 Deform 实现：放在渲染侧程序集。
- **资产 Block：** `SkeletonBlock`（父索引按父先子后排序、参考姿势、骨骼名称哈希）、`AnimationClipBlock`（编码器标识、编码数据、时长、采样率、事件、根运动）、`BoneMaskBlock`（每根骨骼的权重）、蒙皮绑定数据（逆绑定矩阵、关节映射）。
- **压缩接口（可替换）：**
  - 导入时：`IAnimationClipEncoder` 把原始曲线编码为 `AnimationClipBlock`。它由项目通过 Microsoft DI 提供，替换方式与 `IClusterVertexEncoder` 相同；默认实现参考 ACL。
  - 运行时：解码器按编码器标识，在片段加载时解析为函数指针，采样时直接调用，不装箱、不做接口分派。解码器同样由项目提供；默认解码器与默认编码器配对。
  - 编码器标识写入 Block，所以读不懂的数据会明确失败，而不是错误地解码。
- **默认编码（参考 ACL）：**
  - 去掉常量轨道与等于参考姿势的轨道；
  - 按片段与分段做范围归约；
  - 逐轨道可变位宽量化；
  - 均匀采样分段；
  - 误差度量使用骨骼空间中虚拟顶点的位移，按骨骼层级累计；
  - 每个片段可以设置误差阈值。

  移植前确认 ACL 的许可证（MIT）要求，并在源码中注明出处。
- **骨骼不是实体。** 姿势按骨骼数组存储，挂点按需成为实体，其变换由姿势动画系统每帧写入（唯一写入方）。
- **姿势存储：**
  - 中间姿势使用 Job 线程内的复用内存，不持久化；
  - 每个实例的最终局部姿势、模型空间姿势与蒙皮矩阵存于世界级的连续姿势存储中，实例通过 `PoseRange` 组件引用自己的区段；
  - 唯一写入方是姿势求值系统。
- **读取口子（不做额外功能）：** `PoseAnimation.ModelPose(world, entity)` 返回只读的模型空间姿势，并提供版本，可作为依赖。命中检测等用途以后在此基础上实现。
- **图：**
  - 姿势节点（`Clip`、`Blend1D`、`Blend2D`、状态机中的片段状态）通过动画图的公开扩展方式加入，图核心中不出现骨骼；
  - 角色图由代码构建器生成，编译后的图数据由多个实例共享；实例上只有 `Timeline`、`GraphParameters`、状态机状态与混合权重；
  - 可编辑的图资产推迟。
- **混合：** 使用 `IValueOps<T>` 的批量版本，为骨骼变换类型提供 SIMD 实现；骨骼遮罩来自 `BoneMaskBlock`。
- **求值顺序：**
  1. 时间线推进；
  2. 按角色并行求值图：采样、混合、合成层；
  3. 后处理阶段（内置的双骨骼 IK 与注视，以及用户系统）；
  4. 层级传播；
  5. 蒙皮矩阵；
  6. 提取。
- **根运动：** 输出 `RootMotionDelta` 组件，由移动系统读取后决定如何应用；变换的唯一写入方仍是移动系统。
- **LOD：** `PoseUpdateRate` 组件按可见性与距离设定求值频率，跳过的帧在两次求值之间插值。
- **蒙皮：** 在 GPU 上以 Deform 实现完成，只处理可见 cluster，结果写入 Deform cache。Deform 路径目前没有代码，作为前置票实现；开始前检查渲染工作流是否已覆盖。

## Testing Decisions

- 只测公开行为：
  - 给定片段与时间，采样结果在容差内与参考值一致；
  - 混合、遮罩、层的结果符合合成规则；
  - 状态机按参数过渡；
  - 事件计数与根运动增量正确；
  - 挂点实体跟随骨骼；
  - `ModelPose` 的值与版本正确。
- 压缩：在测试数据集上误差不超过阈值；替换编码器与解码器的测试证明接口确实可替换。
- 导入：沿用资产测试的方式（`AssetImportTests`、`ImportContextTests`），检查导入后的 Block 内容。
- 蒙皮：D3D12 与 Vulkan 的读回结果，与 CPU 参考实现在容差内一致。
- 主接缝：无头 World 帧驱动（同 SomeUI），加上资产导入测试与 GPU 读回测试。
- CPU 性能：独立基准，只记录数值，不作为成败判据。渲染性能场景推迟决定。

## Out of Scope（推迟）

- 物理控制（布娃娃、受物理驱动的混合）：等物理系统（AVBD）就绪后另立规格。
- 需要地形与物理查询的 IK（脚部贴地等）：随物理系统一起规划。双骨骼 IK 与注视不依赖物理，在本规格内。
- 不同骨架之间的重定向。
- 可编辑的状态机与混合树资产，以及动画编辑器。
- 基于姿势的游戏功能（命中检测等）：只保留 `ModelPose` 读取口子。
- 渲染性能验收场景的选择。
- 表情与 morph target、布料与头发。
