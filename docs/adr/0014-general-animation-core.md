# 动画是引擎级的通用库：一个核心加两种数据形态

动画是引擎级的库。核心依赖 ECS、ECS.Systems、Job，以及 Core 中的通用值与 DevelopmentCheck；调用方可以把它用于游戏、界面与其它领域。它由一个通用核心和两种数据形态组成：

- **核心：** 时间线、值运算与曲线、动画层与混合规则、图的构建与融合。
- **属性动画：** 按组件编号与生成字段编号引用组件中的叶值，供界面、FLIP 与游戏渐变使用。字段访问由声明解析为实际 CLR 偏移或类型化路径。
- **姿势动画：** 整套骨骼姿势，供引擎动画子系统使用。

二者不互相替代：把骨骼表示为字段轨道会失去压缩与 SIMD，把字段动画表示为姿势缓冲又会为少量字段付出整套姿势的代价。

设计目标与对应做法：

| 目标 | 做法 |
|---|---|
| 保留类型与批量优化机会 | 完整保留值、值运算、参数、状态及求值器五种泛型类型；异构热入口通过 managed 函数指针进入包含循环的具体批次，批内使用静态算法与字段访问 |
| 少结构变化 | 启动、停止、重定目标只修改缓冲元素与可启用组件的启用位；独立实体池化 |
| 少指针追逐 | 能展开成一条时间线的图融合为一个实体；单目标动画内联在目标自身上 |
| 是库而不是内置 | 没有注册表与管理类；内置值类型、曲线、节点与系统和用户扩展地位相同 |

动画层是显式的通用概念：按顺序叠加，每层有模式、权重与遮罩；层权重本身可以被动画。

SomeUI 项目的 `Anim` 与 FLIP 只作为语义参考：`To`/`By`、弹簧重定目标时保留速度、确定性的分层合成、FLIP 只写独立的呈现偏移。它的实现方式（委托访问字段、接口分派、管理类、反向索引、动画完成即销毁实体）不沿用。

用户在 2026-10-03 确定。设计细节见 Wiki [[architecture/Animation|Animation]]。

2026-10-16 确认[强类型执行与统一字段访问规格](../Animation-Typed-Execution-Spec.md)。组件根、算法参数与状态采用各自的 `struct` 约束，允许托管引用；属性叶值保留 `unmanaged` 约束。ECS 的 `IFieldAccess<TComponent, TValue>` 统一生成与手写访问，引用对象内的写入同时沿根组件版本与叶值公开写入行为发布变化。

共享定义持有参数、字段路径及图关系；实例持有时间、共同端点、来源输出与类型化算法历史。声明和编译建立类型组合、容量、来源次序与输出范围；参数更新、重定目标和算法替换沿公开生命周期处理。层权重先于普通字段合成，完成保持值在相关输入变化时参加合成。内置与用户算法、条件、节点及系统使用同一公开能力；构建与装载的低频多态、批次分发和标量曲线回调分别计入实际成本。

姿势动画采用相同的时间、完成汇总、值运算、层与图扩展规则，资产持有片段参数和采样数据，实例持有采样时间与算法历史，最终姿势保存在连续姿势存储中。骨骼数组的采样、混合和后处理在具体批次内执行，详细分工见[姿势规格](../Pose-Animation-Spec.md)。
