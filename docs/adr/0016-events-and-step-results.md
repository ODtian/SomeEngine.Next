# 生产者持有事件日志与步结果，消费者显式登记读取

ECS 销毁事实、查询成员进出和物理事件都需要独立的消费者进度，以及与 Job 资源访问对应的完成点。通用事件日志与步结果访问放在 `SomeEngine.Job`：生产者持有具体数据，消费者登记后取得读取范围和完成依赖，普通 Job 或 kernel 构成数据修改阶段。该决定由 2026-11-08 的 D2、D3、D4、P2、P3、P4 确定。

[ADR 0003](0003-transactional-relations-and-hierarchy.md) 的主值与派生职责继续成立：Parent、关系端点和载荷保存关系事实，Children 与邻接由它们维护。成员日志从这些原生 Added、Changed、Removed 事实及查询匹配结果派生；原生事实仍由需要旧值或增量维护的消费者直接读取。本决策以普通阶段和拉取式消费承接原扩展回调，以显式候选 World 承接整批原子流程；当前范围和存储实现由 [ECS 重构规范](../../wiki/architecture/ECS/Rebuild/Index.md) 持有。

事件按产生顺序编号，读取者从登记时的尾序号开始，各自确认已消费范围。连续存储由最慢读取者的进度决定回收；空间增长计入资源账，长期停滞通过统一 validation 报告。带持久标识的读取进度与对应未消费内容进入存档，匿名读取者用于当前执行期间。显式读取范围固定一次观察的上下界，追加产生的新区间沿独立写权限执行。

步结果由各生产者提供具体视图，通用的 `StepAccess` 表达完成点与读取资源。CPU、GPU 阶段分别持有自己的数据，跨执行者传输沿显式完成点安排；登记 CPU 读取者是设备事件回读的依据。具体存储和视图继续由生产者表达，从而保留连续数据与具体类型的批量操作。

普通命令回放发布成功前缀的原生事实。需要整批原子结果时，在候选 World 执行，成功后交接数据；源 World 的既有查询和读取者可以通过显式恢复继续使用。该边界对应 D7，行为通过成员日志及候选 World 的公开测试验证。
