状态：进行中。三场景已完成一分钟内的稳定采样；1024 球的 1 ms 目标尚未完成，Bistro/Sponza 仍继续优化。

DefaultGame 现在提供同一窗口内的 1024 球、Sponza、Amazon Bistro 场景选择。
F1 打开测试面板；F2/F3/F4 切换场景；F9 测量全部场景；F10 记录全部场景的 CPU trace。
场景列表由 Game.App 构建生成的 `test-scenes.json` 明确指定内容目录，不在启动时搜索其他内容缓存。

内容构建不属于性能计时。测量脚本启动同一个 DefaultGame，通过 F9 操作游戏内的测试平台，
包括程序启动在内最多约 60 秒；超时会终止该次脚本启动的进程并失败。`-Trace` 选择 F10。
未收敛、异常、未测到全部场景均不能作为性能通过。结果在程序输出目录的 Performance 子目录；
诊断后应将有用结论记入此类长期文档并删除临时 trace、分析 JSON 和图片。

测量保留 TAA、VSM 和异步计算，关闭 VSync 和采样期间的面板绘制。1024 球使用场景运动，
导入场景使用静态行为，固定动画步长为 1/60 秒。流送请求持续归零后才采样；
报告包括帧耗时、CPU 侧 Prepare/Reconcile/Execute 阶段耗时，以及驻留页和流送请求数。
这些都是 elapsed time，不能当作独立 GPU 时间或 CPU 利用率。
Release 测试程序设置 `TieredCompilation=false`，避免一分钟内测试混入 JIT 分层切换；
跨版本比较必须使用同样设置，带 trace 与不带 trace 的结果分开比较。

## 已确认的问题

1. 导入场景构建原先仅在首次复制公共 shader，重建后仍可能加载旧内容。
   当前引擎代码与旧 Sponza 内容实际触发了 11/12 个资源绑定不一致错误。
   导入构建现每次更新并登记公共 shader/pipeline 资产，同时保留场景自己的几何、材质和 World。
2. 每个材质独立创建同一 shader，导致重复管线和无法合并的材质分组。
   加载过程现在将已经创建的对象直接赋给 `Material.Shader` 和纹理属性。
   未增加资源管理集合；资产加载器仍只管理文件。场景释放自己创建的依赖，
   材质释放不会销毁外部传入的共享对象。
3. 渲染图对每条改变的顺序边重复遍历全部上游与下游。
   现在按整批变化各遍历一次；交集可能保守地扩大重新分析范围，但不遗漏依赖。
4. 流送一次改变很多顺序关系，调度原先逐条修复同一区间。
   现在对冲突涉及的区间统一排序，区间外保留原位置。
5. 流送页数增加后，同一次提交里相同读范围的资源边界状态重复重建。
   当前正在验证相邻相同读取的状态计算合并，资源访问声明仍然完整保留。

## 帧末资源回收与完成查询

详细 trace 定位到 Bistro 每帧约 2,330 次 `ID3D12Fence.GetCompletedValue`。
原因包含两条重复路径：每个纹理的帧末回收对象分别保存并检查同一批队列完成条件；
每个纹理完成回调调用 `RenderDevice.TrackSubmission` 时又主动检查回收状态。

现在同一帧登记的回收对象合为一批，只有一组完成条件，实际资源仍各自保存其堆分配信息。
帧取消时仍等待先前已提交的工作，完成回调抛异常也不会漏掉回收登记。
`TrackSubmission` 只登记各队列最大完成值，回收检查使用原有的帧边界 `CollectCompleted`。
这没有增加材质依赖集合，也没有改变持久图拓扑或 Game world → Rendering world 数据通路。

相同 1280×720、256 MiB、TAA/VSM/异步计算开启、固定优化 JIT、trace 关闭：

在 Bistro 的 658 个采样帧中，完成查询共 26,581 次，即约 40.4 次/帧，

详细 trace 只用于定位，不混入上表的无 trace 结果。

这两项分别验证当前帧以及取消下一帧时的 GPU 延迟释放，只使用公共 API。

## 材质输入调用频率

对 Cluster 更新增加四个粗粒度阶段：材质输入、驻留范围声明、帧资源绑定和帧上传。
采样阶段的 Bistro 材质输入约 0.848 ms，上传约 0.067 ms，驻留读取声明约 0.047 ms；
小球的材质输入仅约 0.010 ms，因此这条优化不会解决小球的大部分剩余成本。

材质输入的消费者关系现在在材质阶段或图连接变化时整理，直接保留 Material 引用和属性索引。
同一个材质属性只准备一次，再填入使用它的各个图输入。纹理准备增加多消费者重载，
有上传时为每个消费者建立依赖；无上传时不遍历消费者。未增加材质资源所有权或资源集合层。
逐帧数据仍经正常图输入交接，并未假设纹理永远不变化。

相同选项、trace 关闭的完整三场景脚本耗时 41.11 秒，退出码 0：
